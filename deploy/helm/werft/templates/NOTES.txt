Werft is installed as release {{ .Release.Name }} in namespace {{ .Release.Namespace }}.

Worker memory
  worker.memoryMb: {{ $memoryMb }} MiB per session. A worker Pod requests its whole
  limit, so a node runs about this many sessions at once:

    sessions per node ~ node allocatable memory / {{ $memoryMb }} MiB

  less the memory other Pods on that node request. Each node's allocatable memory:

    kubectl get nodes -o custom-columns=NODE:.metadata.name,ALLOCATABLE:.status.allocatable.memory

  When no node has room, a new session waits for one: the session API shows
  wait_reason waiting_for_capacity.
{{- if lt $memoryMb 4608 }}
  Below 4608 MiB, resuming a large transcript with no compaction can reach the limit.
{{- end }}
{{- if and .Values.codexSandbox.enabled (eq .Values.codexSandbox.provider "disabled") }}

Codex sandbox
  codexSandbox.provider is disabled, so this installation has no Codex sandbox: a session
  on a Codex image fails with CODEX_SANDBOX_NOT_INSTALLED. To use Codex, set
  codexSandbox.provider=installer (the chart then creates a ClusterRole, its binding and an
  admission policy, which needs cluster-scoped permissions), or have a cluster admin put the
  profile on the nodes and label them first, and set codexSandbox.provider=external.
{{- end }}
