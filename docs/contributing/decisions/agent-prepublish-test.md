# 결정(설계): 게시 전 시험 — 에이전트 공개 상태와 미리보기

- 상태: 설계. 오너 승인 2026-11-20. 원문: "게시 전 시험 — 에이전트를 만들고 미리 테스트해보는 용도인지 확인이 필요해. 에이전트 생성 후 공개/미공개 상태 지정이나 미리보기 같은 기능을 어떻게 구성할지 검토해 봐야겠어."
- 기준 커밋: `origin/main` `f3c650f4e`. 아래 `파일:줄`은 이 커밋 기준이다.
- 관련 결정: [에이전트 담당 팀과 액션 RBAC](agent-rbac.md)(안쪽·바깥쪽), 에이전트 소유·회수·승계 설계(별도 PR, 같은 세션 시작 차단 자리를 쓴다).
- 시안: 오케스트레이터가 게시한 HTML 시안(PR 본문에 링크).

## 요약

| 항목 | 결론 |
|---|---|
| 용도 | 맞다. 만든 사람이 팀에 내놓기 전에 직접 돌려 보는 기능이다. 지금은 저장하는 순간 팀 전체가 쓰는 상태가 되어 그 단계가 없다 |
| 공개 상태 | 새 칸을 만들지 않는다. **게시됨** = 활성 release가 있다. **미게시** = 없다. 미게시 에이전트는 그 에이전트의 관리자와 워크스페이스 `owner`·`admin`에게만 보인다. 게시되면 지금 규칙(안쪽 ∩ 사용 범위)대로 보인다 |
| 미리보기 | 활성화하지 않은 release로 관리자가 혼자 돌리는 세션. 세션 만들기 요청의 `preview: true`. 웹·API의 사람만, Slack은 안 된다. 공유 범위는 만든 사람 하나로 고정된다 |
| 게시 | 시험한 release를 지금의 활성화(`POST /v1/agents/{id}/activate`)로 켠다. 버전·롤백 흐름은 그대로다 |
| 저장과 게시 분리 | 저장 요청에 `activate: false`를 더한다. release는 만들지만 켜지 않는다. 기본값은 지금처럼 켠다 |
| 콘솔 | 새 에이전트 흐름이 이름 → 하는 일 → **미리 써 보기** → 채널 연결이 된다. 게시된 에이전트는 설정 저장 옆에 "저장만 하고 미리 써 보기"를 두고, release 탭의 켜지 않은 release에 "미리 써 보기"를 둔다 |

## 결정 1: 공개 상태는 활성 release로 정한다

- **게시됨**: `active_release_id`가 있다. **미게시**: 없다. 새 칸(`published_at`, `visibility`)을 만들지 않는다. 활성 release 없이 게시된 에이전트나, 활성 release가 있는데 미게시인 에이전트는 둘 다 뜻이 없다.
- 미게시 에이전트는 그 에이전트의 관리자(개인 관리자, 관리자 팀 구성원, 담당 팀 `lead`)와 워크스페이스 `owner`·`admin`만 안쪽이다. 담당 팀 `member`에게는 지금 바깥쪽이 받는 답과 같다. 목록과 counts에 없고, 상세는 `404`다. `insideAgent`에 "활성 release가 있거나, 관리자이거나, 워크스페이스 관리자"를 더하면 목록·counts·상세·세션 공유가 한 번에 따른다.
- 게시된 뒤의 "권한 있는 사용자"는 지금 규칙 그대로다. 안쪽(담당 팀 구성원 포함)이고, 사용 범위가 `private`이면 그 팀들까지다. 사용 범위 설정을 공개 상태로 쓰지 않는 이유: 사용 범위는 게시된 에이전트를 누가 쓰는지를 정하는 것이고, 미게시 동안에는 팀을 하나 이상 골라야 하는 `private`로도 "관리자만"을 표현하지 못한다.
- 활성화 실패로 활성 release가 아직 없는 에이전트(counts `draft`)도 미게시다. 지금도 담당 팀 구성원은 이 에이전트를 쓰지 못하므로 잃는 것은 목록의 한 줄뿐이다.
- 게시를 되돌리는 "비공개로 돌리기"는 만들지 않는다. 활성 release를 비우는 동작이 지금 없고, 쓰던 사람의 Slack·API 경로가 한꺼번에 끊긴다. 멈추는 것은 지금의 일시 정지(`paused`)로 한다.

## 결정 2: 미리보기는 켜지 않은 release로 관리자가 혼자 돌리는 세션이다

- 세션 만들기(`POST /v1/sessions`)에 `preview: true`를 더한다. 이때만 승인되지 않은 release로 시작할 수 있다. 조건은 넷이다.
  1. 요청자가 사람이다. 웹 로그인 또는 그 사람의 개인 key. 에이전트 key와 Slack은 안 된다(`preview`를 보내면 `400`).
  2. 그 release의 에이전트를 관리한다(`agent.manage`, 워크스페이스 관리자 포함). 아니면 `release_unapproved`로 지금과 같이 답한다. 미리보기가 있다는 사실을 바깥에 알리지 않는다.
  3. release가 그 에이전트의 것이고 연결·모델이 지금 쓸 수 있다(`RELEASE_SPEC_UNAVAILABLE`은 그대로).
  4. 에이전트가 `active`다. 소유자 없음으로 막힌 에이전트도 미리보기는 된다. 승계하려는 관리자가 확인할 길이 있어야 하기 때문이다. 단 관리자가 없으면 워크스페이스 관리자만 해당한다.
- 승인된 release(활성 또는 옛 release)에도 `preview: true`를 보낼 수 있다. 같은 표시가 붙을 뿐이다.
- 세션 행에 `preview boolean NOT NULL DEFAULT false`를 둔다. 상세·목록에 `preview`로 나온다. release가 나중에 게시돼도 이 값은 바뀌지 않는다.
- **공유 범위는 만든 사람 하나로 고정한다.** 미리보기 세션의 공유를 넓히는 요청은 `409`다. 아직 팀에 내놓지 않은 동작과 그 transcript가 담당 팀에 보이지 않게 하려는 것이다. 워크스페이스 관리자의 감사 읽기(`session.audit_read`)는 지금처럼 된다.
- 미리보기 세션도 진짜 세션이다. 같은 worker, 같은 도구·권한 모드·GitHub 설정·자격 증명 연결·호출자 상한으로 돈다. 사용량과 비용도 그대로 센다. 따로 sandbox를 만들지 않는 이유: 다르게 돌면 게시 뒤의 동작을 시험한 것이 아니다. push 승인 같은 외부 쓰기 확인은 release 설정대로 사람에게 묻는다.
- Slack에는 나타나지 않는다. Slack 세션은 에이전트의 활성 release로만 시작하고, 미리보기 세션은 Slack 링크를 갖지 않는다. 미게시 에이전트에 Slack 앱을 붙이는 것은 지금처럼 되지만(설치 준비), 멘션은 "아직 게시되지 않은 에이전트"라는 짧은 안내를 받는다.
- 성과 판정(achievements)에서는 미리보기 세션을 뺀다. 시험 실행이 팀 성과로 세어지지 않게 한다.

## 결정 3: 저장과 게시를 나눈다

- `POST /v1/agents`와 `PATCH /v1/agents/{id}`의 저장 요청에 `activate`(기본 `true`)를 더한다. `false`이면 버전과 release를 만들고 켜지 않는다. 응답의 `release.status`는 새 값 `saved`이고 `release_id`가 있다.
- 기본값을 `true`로 두는 이유: 지금의 API 사용자와 SDK는 저장이 곧 적용이라고 믿고 있다. 콘솔이 `false`를 보낸다.
- 게시는 지금의 활성화다(`POST /v1/agents/{id}/activate` `{"release_id"}`). 활성화가 `approved_at`을 적고, 활성 release가 생기면서 [결정 1](#결정-1-공개-상태는-활성-release로-정한다)에 따라 팀에 보인다. 자격 증명 연결 확인(`CREDENTIAL_UNBOUND`)과 revision 경합 처리도 그대로다.
- 게시된 에이전트에서 `activate: false`로 저장한 변경은 활성 release를 건드리지 않는다. 팀은 계속 이전 release를 쓰고, 관리자는 새 release를 미리 써 본 뒤 release 탭에서 켠다. 롤백도 지금처럼 이전 release를 다시 켠다.
- `draft_version_id`는 지금 뜻("적용이 실패한 변경")을 그대로 둔다. `activate: false` 저장은 실패가 아니므로 이 칸을 쓰지 않는다. 켜지 않은 release 목록은 release 탭이 이미 보여 준다.

## 콘솔

시안: 오케스트레이터가 게시한 HTML 시안. 화면은 넷이다.

1. **새 에이전트 흐름.** 이름 → 하는 일 → 미리 써 보기 → 채널 연결.
   - "하는 일"의 버튼은 "저장하고 미리 써 보기"다(`activate: false`).
   - "미리 써 보기" 단계: 위에 "아직 게시하지 않았습니다. 지금은 나와 워크스페이스 관리자만 이 에이전트를 봅니다." 알림. 메시지를 보내면 미리보기 세션이 시작되고, 답과 세션 링크가 보인다. 여러 번 보낼 수 있다(세션 하나에 이어서). "설정 고치기"는 이전 단계로 돌아가 새 release를 만들고, 다음 메시지는 새 미리보기 세션으로 간다.
   - "게시" 버튼: 확인 창 "게시하면 담당 팀 {팀}이 이 에이전트를 쓸 수 있습니다." → 활성화. "나중에 게시"를 누르면 미게시 상태로 에이전트 상세로 간다.
   - 채널 연결은 게시 뒤에만 연다.
2. **에이전트 목록.** 미게시 에이전트는 상태 칸에 "미게시"로 보인다(관리자에게만 보이는 행이다).
3. **에이전트 상세(미게시).** 위에 알림 "아직 게시하지 않았습니다"와 "미리 써 보기", "게시" 버튼.
4. **release 탭.** 켜지 않은 release의 행에 "미리 써 보기"(미리보기 세션 시작)와 지금의 "켜기"(=게시). 설정 저장 버튼 옆에 "저장만 하고 미리 써 보기"를 둔다.
- 미리보기 세션은 세션 목록과 상세에 "미리보기" 표시가 붙는다.

## 하지 않는 것

- 별도 sandbox 실행 환경, 가짜 도구, 외부 쓰기를 막는 모드. 미리보기는 진짜 실행이다.
- 공개 상태 칸, 게시 취소, 게시 예약.
- 다른 사람에게 미리보기를 보여 주는 공유(검토자 초대). 필요해지면 미리보기 세션의 공유를 지정한 사람까지 여는 것으로 연다.
- 미리보기용 비용 상한. 지금의 세션 상한과 호출자 상한이 그대로 적용된다.

## 오너 확인이 필요한 것

아래는 이 문서가 정한 기본값이다. 바뀌면 후속 PR로 고친다.

- 공개 상태는 활성 release 유무로 정하고 별도 칸을 두지 않는다.
- 미게시 에이전트는 담당 팀 `member`에게도 보이지 않는다.
- 미리보기는 진짜 실행이다(sandbox 없음). 비용·외부 쓰기도 실제와 같다.
