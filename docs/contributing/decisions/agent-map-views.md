### 지금 지도가 못 하는 것

- **전체가 아니다.** 최근 50개와 대기 세션 최대 50개를 합칠 뿐이라, 오래된 실행·유휴 세션은 빠질 수 있고 종료 수도 읽은 목록 안의 수다(`agent-map.tsx:66-105`, `use-agent-map.ts:100-109`). 두 뷰가 같은 한계를 물려받는다.
- **그래프는 별 모양 요약이다.** 실행 트리는 깊이 우선으로 펴진 뒤 모든 행이 같은 루트에 연결된다. 부모·깊이 정보가 어댑터에서 빠진다(`run-tree.ts:618-628`, `board-data.ts:89-99`, `relation-graph.tsx:67-83`).
- **세션 사이 관계 데이터가 없다.** contracts에 부모 세션·위임 필드가 없다. 세션 사이 관계(위임, 에이전트 간 메시지, 사람 승인 대기)를 세션 데이터와 API에 두는 일은 94S-928이 맡는다. 이 설계는 그 티켓의 상태나 최종 계약을 새로 확정하지 않는다.

## 두 번째 뷰: 줌 캔버스

한 장의 넓은 평면 위에서 화면(카메라)만 움직인다. 확대 정도에 따라 보이는 정보가 바뀐다(의미 줌). 전체를 먼저 보다가 에이전트·세션·실행으로 확대해 들어가는 화면 이동만 참고하고, 어떤 제품의 외형도 따르지 않는다.

| 단계 | 보이는 것 |
|---|---|
| L0 전체 | 점 = 세션, 색 = 상태 |
| L1 리드 | 에이전트 묶음 안의 세션 카드 |
| L2 세션 | 그래프 뷰의 관계 패널과 같은 실행 행 |
| L3 카드 | 도구 호출 전체 목록 |

- **장면 이동.** 노드를 클릭하거나 Enter를 누르면 카메라가 그 노드로 이동하며 확대한다. Esc나 "위로"로 한 단계 나온다. 드래그·휠·핀치는 보조 수단이다.
- **관계선.** 기존 간선 종류(`delegation / approval / request / response / waiting`, `types.ts:30-35`)를 선 모양과 화살표로 구분한다. 세션 사이 선은 데이터가 생긴 뒤에 켠다(단계 C).
- **경로 재생.** 시간순으로 일이 넘어간 길을 한 단계씩 다시 보여 준다. 한 세션 안 재생은 이벤트에서 재구성할 수 있지만, 지금 모델은 최신 상태를 모은 것이라 과거 시점의 상태를 곧바로 뽑지 못한다(`types.ts:14-20`, `37-62`). 세션 사이 재생은 메시지 ID, 보내는 쪽·받는 쪽, 답과의 짝, 같은 시각의 순서, 권한상 보이지 않는 구간의 처리를 계약으로 정해야 한다.

### 캔버스를 시작하기 전에 정할 것

- **"리드"가 무엇인가.** 등록된 에이전트(API의 `agent.id`, `packages/contracts/src/api/session.ts:475-489`)이면 지금도 묶을 수 있다. 다른 세션을 지휘하는 세션이면 관계 데이터가 있어야 한다. 이름은 바뀔 수 있어 묶는 열쇠로 쓰지 않고, 화면용 `MapSession`이 이름 문자열만 남기는 부분(`board-data.ts:58`)을 ID 보존으로 고친다. A2a는 "리드 = 등록 에이전트"로 시작한다.
- **"전체"가 무엇인가.** 읽을 수 있는 전체 세션인지, 최근 N개 + 대기인지 L0의 이름과 수용 기준을 정해야 한다. 기존 목록 API의 페이지·검색·에이전트 필터와 무한 조회 도우미는 재사용할 수 있어, 새 요약 API가 필요하다고 먼저 단정하지 않는다(`contracts/src/api/session.ts:663-680`, `core/src/queries.ts:686-698`).

## 뷰를 고르는 방법

### 뷰 전환 UI

| 항목 | 정한 것 |
|---|---|
| 위치 | 제목 아래 상태 줄의 오른쪽(`packages/react/src/components/agent-map/agent-map-page.tsx:36-51`). 전환 컨트롤은 두 뷰 바깥, 페이지 쪽에 두어 뷰를 바꿔도 사라지지 않는다 |
| 컨트롤 | 버튼 두 개("그래프", "캔버스")를 `role="group"` + 이름 "지도 보기"로 묶고, 고른 쪽에 `aria-pressed="true"`를 준다. 레인 카드가 이미 같은 방식이다(`lane-board.tsx:46-50`). 이유는 이미 쓰는 방식이고 화살표 키 규칙을 따로 정하지 않아도 되기 때문이다. 탭이나 라디오도 수동 활성화로 쓸 수 있어 버튼만이 길은 아니다. 둘 중 정확히 하나만 눌린 상태여야 한다는 규칙을 수용 기준에 둔다 |
| 키보드 | Tab으로 닿고 Enter 또는 Space로 바꾼다. 전환용 단축키는 두지 않는다(입력·슬라이더 조작을 가로챌 수 있다). 바꾼 뒤에도 초점은 눌린 버튼에 남는다 |
| 기본 뷰 | 그래프. 지금 화면이 회귀 없이 그대로이고, 캔버스는 A2a 측정 전까지 검증판이다. 기본을 바꾸는 일은 값 하나를 바꾸는 별도 결정이며 이 문서는 바꾸자고 하지 않는다 |
| 좁은 화면 | "요청한 뷰"와 "실제로 보이는 뷰"를 나눈다. md 미만에서는 요청이 캔버스여도 그래프 뷰(트리)를 보이고, 전환 컨트롤 자리에 "이 화면 너비에서는 그래프로 보입니다"라는 한 줄을 둔다. 주소와 설정의 값은 그대로 두므로 넓히면 캔버스로 돌아온다. 주소가 가리키는 것은 요청한 뷰다 |
| 껍데기와 뷰 본체 | 머리글·전환 컨트롤·알림은 두 뷰 바깥의 껍데기가 갖고, 뷰 본체는 둘 중 하나만 마운트한다. 지금 `AgentMapPage`는 머리글과 `AgentMap`을 한 컴포넌트에 묶고 있어(`agent-map-page.tsx:27-55`) A1에서 나눈다. 고르지 않은 뷰는 CSS로 숨기지 않는다 |
| 언마운트의 한계 | 언마운트는 비용을 모두 없애지 않는다. 동적으로 불러온 캔버스 모듈은 내려가지 않고, 목록·대기 요청·선택 세션 스트림도 뷰 위에서 계속 돈다(`agent-map.tsx:66-69`, `115-129`, `194-207`). 캔버스는 이 조회 훅을 복제하지 않고 props로 받는다. 그래프 뷰 안에서 그래프와 트리를 둘 다 마운트하는 비용(`relation-panel.tsx:66-81`)은 그대로 남는다. 캔버스 코드를 불러오다 실패하면 그래프 뷰로 돌아간다 |

### 두 뷰가 함께 쓰는 상태

규칙 하나로 정한다. **선택한 세션과 데이터는 라우트에 한 번만 두고, 뷰는 어디를 어떻게 보는가(카메라, 확대한 묶음, 스크롤)만 따로 가진다.** 캔버스에서 에이전트 묶음으로 확대한 것을 그래프 화면의 공유 필터로 만들지 않는다. 확대했을 뿐인데 그래프로 돌아오면 다른 에이전트의 카드가 사라지는 것은 오너가 요청하지 않은 화면 변경이기 때문이다.

| 상태 | 공유 위치 | 단계 | 뷰를 바꿀 때 |
|---|---|---|---|
| 선택한 세션 | 지금의 `chosen`을 그대로 쓴다 | A1 | 유지한다. 캔버스는 열릴 때 그 세션 쪽으로 카메라를 맞춘다. 사라졌으면 지금처럼 `firstCard`로 돌아간다. 선택 ID가 같은 채 뷰만 바뀌면 이벤트를 다시 구독하지 않는다. 선택 세션 행은 어느 세션의 것인지 ID를 함께 들고 있어, 선택이 바뀐 첫 렌더에 이전 세션의 행이 새 제목 아래 보이지 않게 한다(수용 기준) |
| 에이전트 묶음(L1에서 확대한 것) | 캔버스 뷰 안의 장면 상태. 라우트에 올리지 않는다 | A2a | 버린다. 그래프로 돌아가도 카드는 줄지 않고, 캔버스로 돌아오면 선택한 세션에서 다시 시작한다 |
| 상태 필터 | 새로 만들지 않는다. 레인(주의·실행·대기열·유휴)이 이미 분류이고 두 뷰가 같은 분류(`laneOf`)를 쓴다 | — | 해당 없음 |
| 시간 범위 | 지금 없다. B에서 목록 조회에 범위를 더할 때 선택한 세션과 같은 자리(라우트)에 둔다 | B | 유지한다. 두 뷰가 같은 목록을 읽으므로 두 뷰 모두 넓어진다 |
| 카메라 위치, 펼침, 스크롤 | 각 뷰 안. 공유하지 않는다 | — | 버린다 |
| 좁은 화면의 패널 전환 | 그래프 뷰 안(`view`를 `panel`로 이름만 바꿈) | A1 | 그래프 뷰에만 있다 |

이렇게 두면 이벤트 구독(`useSessionRunTree`)과 5초 폴링이 뷰 위에 있어 뷰를 바꿔도 다시 받지 않는다. 정보 동등 원칙도 같이 세운다. **데이터는 두 뷰가 같고 표현은 달라도 된다.** 한 뷰에만 보이는 정보가 생기면 다른 뷰에 글로 된 항목을 둔다(단계 C·D).

캔버스는 보드 데이터를 그대로 쓰지 않는다. 보드가 만든 `board.sessions`는 종료된 세션을 이미 뺐고, 사용자가 고정한 레인(`pinnedLane`)이 실제 상태보다 앞선다(`board-data.ts:199-223`). 그대로 쓰면 캔버스는 "전체"가 아니라 보드의 배치 정책을 물려받는다. A2a에서 세션 원본과 보드 배치 투영을 나눠, 캔버스는 원본을 읽게 한다.

나중에 사용자가 거는 필터(에이전트 등)를 도입하기로 따로 정하면 그때 아래를 함께 설계한다. 이 문서는 그 필터를 만들자고 하지 않는다.

- 필터에 가려진 선택 세션(교체한다면 `chosen`도 같이 갱신, 필터를 지워도 되살아나지 않게)
- 빈 결과
- 종료 수·"다시 정리"·알림의 범위
- 숨긴 카드가 보드의 배치 기억에서 지워져 다시 나타날 때 새 카드로 취급되는 문제

### 뷰 고정: 주소와 사용자 설정

| 수단 | 쓰는 것 | 근거 |
|---|---|---|
| 공유 링크 | 주소 쿼리 `?view=graph` 또는 `?view=canvas`. 지도 라우트에 `validateSearch`를 더한다 | `/sessions`가 같은 방식이다. 모르는 값은 버리고, 바꿀 때는 `replace`라 뒤로 가기에 전환 기록이 쌓이지 않는다(`sessions.tsx:79-92`, `113-119`) |
| 개인 설정 | 브라우저 `localStorage`의 사용자별 키(예: `ap.map.view.<userId>`). 막혀 있으면 이번 방문에만 유지한다 | 에이전트 화면의 카드/표 선택이 같은 방식이다(`apps/web/src/components/agent-view.ts:7-36`). 서버에 저장하는 사용자 설정 계약은 찾지 못했다 |

**둘이 다를 때**

1. **주소가 이긴다.** 링크를 받은 사람은 보낸 사람이 보던 뷰로 열린다. 주소 값이 없거나 모르는 값이면 설정으로, 설정도 없거나 읽을 수 없으면 기본(그래프)으로 연다.
2. **설정은 사용자가 컨트롤을 눌렀을 때만 바뀐다.** 받은 링크로 한 번 본 것이 내 설정을 덮어쓰지 않는다.
3. 컨트롤을 누르면 설정을 저장하고 주소도 같은 값으로 바꾼다. 설정으로 열린 경우에도 주소에 `?view=`를 채워(`replace`), 주소창을 복사하면 요청한 뷰가 그대로 전해지게 한다.

**구현 계약**

- `validateSearch`만 믿지 않는다. 루트가 원시 쿼리를 그대로 넘기므로 `/sessions`는 화면에서 한 번 더 검증한다(`sessions.tsx:97-99`, `router.tsx:98-100`). 지도 화면도 순수 파서로 다시 검증하고, 유효한 주소 값을 그 렌더의 단일 기준으로 삼는다.
- 주소 값이 없거나 무효일 때만 설정을 동기로 읽는다. 주소를 채우는 `replace`는 현재 주소와 목표가 다를 때만 하고, 사용자의 누름과 열릴 때의 정규화가 같은 쓰기를 두 번 하지 않게 쓰는 곳을 한 군데로 둔다. 지금 `/sessions`의 `replace`는 사용자가 필터를 누를 때의 동작이고, 열릴 때 정규화하는 선례는 아니다.
- `replace`이므로 뒤로 가기는 이전 뷰를 되살리지 않는다. 뒤로/앞으로로 들어올 때는 저장된 설정이 아니라 주소가 이긴다.
- 수용 기준: 기존 메모리 히스토리 테스트 장비(`apps/web/src/test-support/render-app.tsx:13-48`)로 무효 값, 저장소 막힘, 연속 클릭, 뒤로/앞으로 뒤의 최종 주소와 마운트 횟수를 확인한다. 잘못된 뷰가 잠깐 보이는 깜박임과 주소 갱신의 반복이 없음은 브라우저에서 확인해야 한다.

한계는 두 가지다. 설정이 브라우저별이라 다른 기기에 따라가지 않는다. 선택한 세션은 주소에 넣지 않는다. 오래된 세션이 목록 밖(최근 50개와 대기 밖)이면 링크가 조용히 다른 세션을 보이게 되기 때문이다. 필요해지면 목록 밖 세션을 따로 읽는 처리와 함께 더한다.

### 그래프 뷰에 남는 보강 후보

아래는 캔버스의 대안이 아니라 그래프 뷰의 독립된 개선이고, 어느 것도 캔버스의 선행 조건이 아니다.

- 실행 트리의 진짜 부모·깊이를 어댑터가 넘겨, 별 모양 대신 중첩 구조로 그린다(`run-tree.ts`의 `children` 사용). 캔버스 L2도 같은 어댑터를 쓰므로 A2b에서 한 번만 만든다.
- 선택 세션 안 경로 목록: 시간순 순서 목록과 한 단계씩 넘기는 버튼, 해당 행과 간선 강조.
- 레인 목록의 검색, 관계 없는 행을 흐리게 하는 집중 보기.
- 데이터가 생기면 `MapSessionNode` 행을 같은 그래프에 추가.

## 라이브러리와 성능

repo에는 그래프·줌·배치·애니메이션 라이브러리가 없다(직접 의존성에서 확인: xyflow, d3, dagre, elkjs, 모션, pixi, konva 모두 0건). 새로 들일 수 있는 후보는 아래이며, 최신 API와 호환은 검증하지 않았다.

| 후보 | 그리는 방식 | 얻는 것 / 대가 |
|---|---|---|
| `@xyflow/react` | DOM 노드 + SVG 간선 | 이동·줌·미니맵·키보드 일부 제공. 카드를 기존 Tailwind 컴포넌트로 그릴 수 있다. 접근성 동작이 우리 기준과 같은지 확인 필요 |
| `d3-zoom` (+ `d3-force` 또는 `elkjs`로 배치) | DOM/SVG에 변환 적용 | 카메라 수학만 맡기고 나머지는 직접. 작지만 접근성은 전부 직접 |
| `pixi.js` 등 Canvas/WebGL | Canvas / WebGL | 노드가 아주 많을 때 유리. DOM이 없어 키보드·스크린 리더·Tailwind 카드를 잃는다. 지금 규모에는 과하다 |
| 직접 구현 (변환 계층 + 순수 카메라 수학) | DOM + SVG | 의존성 0. 제스처·초점 구현비는 우리 몫이다 |

버전은 도입을 정하는 시점에 확정한다. 직접 구현과 라이브러리 중 무엇이 싼지는 같은 제스처·초점 요구로 만든 작은 검증(A2a)에서 비교해 정하고, 한쪽을 미리 못 박지 않는다. 캔버스가 선택형 뷰이므로 라이브러리 비용은 캔버스를 고른 사용자에게만 내려가는 늦은 불러오기 덩어리로 가둘 수 있다.

### 세션 수백 개에서 무엇이 먼저 깨지나

숫자는 측정하지 않았다. 아래는 코드로 확인되는 제약이고 임계값은 측정 전 가설이다. 비용을 세션 수 N, 선택 세션의 실행 수 R, 그 세션의 이벤트 수 E, 별도 조회가 필요한 대기 세션 수 K로 나눈다. 1~4번은 두 뷰가 공통으로 가진 비용이라 뷰 선택과 무관하게 남는다.

1. **목록 누락이 먼저다.** 지금 화면은 300개를 읽지도 않는다(N은 최대 100). 관계 그래프는 선택한 세션 하나만 그리므로 "세션 300개 = 간선 300개"가 아니다(`agent-map.tsx:37-46`, `203-207`).
2. **대기 세션 추가 조회.** 활동에 대기 도구가 안 보이는 `needs_input` 세션마다 pending-requests 조회가 하나씩 생기고 5초마다 다시 읽는다. K가 크면 초당 약 K/5건이 더 나간다(`agent-map.tsx:115-129`, `core/src/queries.ts:895-905`).
3. **폴링마다 보드 재생성.** 데이터가 같아도 `readAt`이 바뀌면 보드를 다시 만들고, 카드 선택 함수도 매번 새로 만든다. 단순 `memo`만으로는 안정되지 않아 props 안정화가 필요하다(`use-agent-map.ts:35-64`, `100-105`, `lane-board.tsx:310-319`).
4. **세션을 바꿀 때 전체 이력 재수신.** 새 builder를 만들고 이벤트 전체를 구독한다. 그래프와 트리를 CSS로만 숨겨 둘 다 마운트하는 점도 실행이 많은 세션에서 비용이다(`use-agent-map.ts:113-155`, `relation-panel.tsx:66-81`).
5. **간선 좌표 (캔버스만).** 지금은 화면 좌표 차이를 SVG 좌표로 쓰므로 줌 컨테이너 안에서는 배율이 겹쳐 틀린 값이 된다(거리 100이 배율 0.5에서 50으로 읽히고 SVG에 또 0.5가 적용). 카메라만 바뀌면 다시 측정한다는 보장도 없다. 간선은 측정 대신 레이아웃 모델의 좌표(또는 역변환)로 계산해야 한다(`relation-graph.tsx:63-98`).
6. **그릴 것의 수 (캔버스만).** 흐름 애니메이션은 실행 상태 간선에만 있다(`relation-graph.tsx:128-161`). 카드마다 툴팁과 초점 가능한 요소가 있어 DOM·접근성 비용은 재 볼 만하다(`ui/src/primitives/relative-time.tsx:15-17`, `37-43`).

**측정 계획 (A2a에 포함).** N·R·E·K와 화면에 보이는 노드 수, 활성 간선 수를 바꿔 가며 처음 로드, 선택 전환, 이동 중 프레임 시간, 메모리, 요청량을 잰다. 뷰를 바꿀 때 걸리는 시간과 되돌아왔을 때 초점·선택이 유지되는지도 잰다. 뷰를 여러 번 오간 뒤에도 활성 스트림·요청·애니메이션 프레임 요청·관찰자·이벤트 리스너 수가 늘지 않는지 센다. "두 뷰가 동시에 안 뜬다"만 확인하면 이런 누수를 놓친다. SVG/DOM에서 Canvas/WebGL로 넘어갈 임계값은 이 측정 뒤에 정한다.

## 접근성

현재 화면은 세션 카드를 버튼으로 선택하고(`lane-board.tsx:46-50`), 좁은 화면 전환 때 패널 제목으로 초점을 보내고 돌아오면 선택 카드로 복원한다(`packages/react/src/components/agent-map/agent-map.tsx:83-99`). 그래프 뷰는 이 동작을 그대로 지키고, 캔버스는 이 동작을 지켜야 한다.

**뷰 전환 컨트롤**

- 버튼 두 개는 Tab으로 닿고 Enter·Space로 바뀐다. 이름은 "지도 보기", 현재 뷰는 `aria-pressed`로 전한다. 언제나 정확히 하나만 눌린 상태다. 색만으로 구분하지 않고 고른 쪽에 표식과 굵기 차이를 둔다. 대상 크기와 초점 링 잘림은 실제 브라우저에서 확인한다.
- 초점: 전환 컨트롤은 두 뷰 바깥의 껍데기에 있으므로 이 버튼으로 바꿀 때 초점은 눌린 버튼에 남는다. 캔버스 안의 "그래프 보기로 전환" 버튼은 전환과 함께 사라지므로, 눌렀을 때 초점을 위쪽 전환 컨트롤(그래프 쪽 버튼)으로 명시해서 보낸다. 새로 마운트된 `AgentMap`은 현재 값으로 초기화되어(`packages/react/src/components/agent-map/agent-map.tsx:75-99`) 마운트만으로는 초점이 복원되지 않는다. 주소로 들어올 때는 누른 버튼이 없어 초점을 옮기지 않는다. 창을 줄여 컨트롤이 사라질 때는 페이지 제목으로 보낸다.
- 알림: 기존 라이브 영역(`agent-map-page.tsx:52-54`)은 폴링이 바꾼 마지막 문장을 다음 변경까지 간직한다(`use-agent-map.ts:67-74`). 거기에 전환 문구를 덮으면 같은 시점의 폴링 알림이 사라지거나 되돌릴 때 이전 알림이 다시 읽힐 수 있다. 껍데기에 전환 알림용 영역을 따로 두고, 전환 알림을 읽은 뒤 비운다. 반복 전환이 매번 한 번씩만 읽히는지, 폴링과 겹쳐도 중복 낭독이 없는지는 A1 수용 기준으로 확인한다.
- 전환 자체에는 애니메이션이 없어, 줄인 동작 설정에서도 달라질 것이 없다.

**키보드 이동**

- 그래프 뷰: 지금 그대로다. 카드는 버튼이고, 좁은 화면에서는 패널 제목으로 초점을 옮긴다.
- 캔버스 뷰: 노드는 하나의 탭 정지점(roving tabindex)이고 화살표로 같은 단계의 이웃 노드로 이동한다. Enter로 들어가고 Esc 또는 Backspace로 나온다. 보이기·맞춤·확대·축소·위로 이동은 모두 버튼으로도 할 수 있어 드래그·핀치 없이 쓸 수 있다.
- 카메라 이동과 DOM 초점 이동을 따로 정의한다. 포인터 이동·줌은 초점을 유지하고, 명시적 들어가기는 도착 장면의 제목 또는 선택 노드로 초점을 보낸다. 나오기는 출발 노드로 되돌리되, 폴링·필터·가상화로 사라졌으면 부모나 목록 제목으로 복원한다.
- 줌으로 숨기거나 교체한 장면의 컨트롤이 탭 순서에 남지 않게 한다. 초점이 있는 요소는 화면 밖 가상화로 언마운트하지 않는다.
- 카드 안의 상대 시간 요소가 이미 `tabIndex=0`이라(`relative-time.tsx:38-43`) 중첩 초점 정책이 필요하다. 장면 이동 단축키가 입력·슬라이더 조작을 가로채면 안 된다.

**줄인 동작 (`prefers-reduced-motion`)**

- 카메라는 보간 없이 바로 이동하고 흐름 점선은 끈다. CSS는 토큰에서 이미 애니메이션을 멈추지만(`packages/ui/src/foundations/use-reduced-motion.ts:3-33`), 스크립트가 제어하는 카메라는 훅을 직접 연결해야 한다. 진행 중 보간과 관성은 설정이 바뀌는 즉시 멈춘다. 캔버스를 처음 열 때 선택한 세션으로 가는 이동도 같은 규칙을 따른다.
- 그래프 뷰는 지금처럼 흐름 애니메이션을 끈다(`relation-graph.tsx:153`).
- 경로 재생은 자동 재생 대신 "다음/이전" 한 단계씩이 기본이다. 일시정지·단계 버튼과 슬라이더에 이름과 현재 값을 붙인다.

**스크린 리더용 목록**

- 그래프 뷰가 첫 번째 대체 경로이지만 "이미 목록이니 동등하다"고 하지 않는다. 지금 그래프의 간선은 보조 기술에서 숨겨져 있고, 글로 된 트리는 md 이상에서 숨겨지며(`relation-panel.tsx:66-81`), 이 트리는 부모·깊이를 버리고 도구 호출을 최근 3개 칩으로 줄인 행으로 만든다(`board-data.ts:89-99`, `108-159`, `run-tree.ts:618-628`). 그래서 관계 구조가 글로 완전히 전해지지는 않는다. 이 빈틈은 그래프 뷰에 이미 있는 것이다.
- 캔버스는 스스로 쓸 수 있어야 한다. 별도 목록을 하나 더 두지 않고 **캔버스의 노드 자체를 중첩 `<ul>`(에이전트 → 세션 → 실행, 관계 방향·종류 텍스트)로 DOM 순서대로 그린다.** 같은 항목이 두 번 나와 읽기·탭 경로가 겹치는 것을 피하기 위해서다. 이를 위해 트리와 전체 호출을 보존하는 공통 표현이 A2b의 명시 산출물이다.
- 캔버스 영역의 첫 항목으로 "그래프 보기로 전환" 버튼을 둔다. 캔버스가 맞지 않는 사람이 어디서든 한 번에 나올 수 있다.
- 상태는 색만으로 전하지 않는다. 행의 상태 문구와 간선 종류 배지(`run-node.tsx:74-90`)를 재사용한다. 장면이 바뀔 때 라이브 영역으로 "에이전트 A, 세션 12개"처럼 알린다.
- 확대 시 대상이 너무 작아지지 않는지, 변환된 평면에서 초점 링이 잘리지 않는지는 실제 브라우저에서 확인한다.

## 구현 크기와 단계

한 숫자로 견적하지 않고 산출물별 상대 크기(S·M·L)로 나눈다.

| 단계 | 산출물 | 선행 조건 | 크기(상대) |
|---|---|---|---|
| **A1** | 뷰 선택 골격. 머리글·전환·알림 껍데기와 뷰 본체 분리, 전환 컨트롤, `?view=` 파서와 위 구현 계약, 개인 설정 저장, 패널 전환 `view`의 이름 변경. 단독으로 내보내지 않는다. 캔버스 선택지를 숨기면 전환·불러오기 실패·재마운트 초점·구독 수를 검증할 수 없으므로 테스트에서는 두 번째 뷰 대역을 실제로 전환해 본다. 사용자가 보는 화면은 달라지지 않는다 | 없음 | S |
| **A2a** | 캔버스 검증판(재생 없음): 전체(최근 N + 대기) → 에이전트 묶음 → 세션 → 실행의 카메라와 장면 이동. 세션 원본과 보드 배치 투영의 분리, 에이전트 ID 보존. 직접 구현과 라이브러리 비교, 성능·누수 측정 | A1, "리드 = 등록 에이전트"로 정의, "전체"의 범위 결정 | M |
| **A2b** | 캔버스를 제품에 붙이기: 트리와 전체 호출을 보존하는 공통 표현, 노드 자체가 중첩 목록인 DOM, 초점 복원, 줄인 동작, 좁은 화면 규칙, 불러오기 실패 시 그래프 복귀 | A2a의 측정 결과와 오너의 계속 결정 | M |
| **B** | 전체 지도 데이터와 시간 범위: 페이지·권한·검색을 포함한 개요 데이터, 가상화, 폴링 부담 줄이기, 범위를 좁혔을 때 종료 수·"다시 정리"·알림의 범위. 두 뷰가 같은 목록을 읽으므로 그래프 뷰도 넓어진다 | A2a의 측정 결과(그래프 뷰만의 필요라면 A2a와 순서를 바꿀 수 있음) | M |
| **C** | 세션 사이 관계 표시(위임·메시지·승인 대기). 캔버스는 관계선, 그래프 뷰는 방향·종류를 글로 적은 관계 목록으로 같은 정보를 보인다 | **94S-928 계약**(부모 세션, 종류, 메시지 간선) | M + S |
| **D** | 경로 재생(세션 안 → 세션 사이). 캔버스에서는 재생, 그래프 뷰에서는 같은 순서를 한 단계씩 넘기는 목록 | 이력·상관관계 계약, 이벤트 재구성(prefix) 모델 | M~L |

- A1부터 시작하되 A2a와 함께 검증한다. A1은 사용자 화면을 바꾸지 않아 위험이 작지만, 두 번째 뷰가 없으면 확인할 수 없는 것이 많다.
- A2a 측정 뒤 오너가 캔버스를 원하지 않으면 A2b로 가지 않고 멈춘다. 그래프 뷰는 영향이 없다.
- C·D는 94S-928 계약이 정해진 뒤에 두 뷰에 함께 올린다. 기본 뷰를 캔버스로 바꾸는 일은 이 단계들에 포함하지 않는다.
- 이 repo의 DOM 테스트는 happy-dom(`setupDom()`)이라 스타일시트·실제 초점·포인터/핀치·배율이 걸린 SVG는 브라우저 검증을 일정에 넣어야 한다. 순수 카메라 수학은 단위 테스트한다.
- 위 크기는 수용 기준별로 다시 산정하지 않은 상대 표기다.
- 구현 티켓: 94S-1468 (단계 A1부터, Backlog). A2a 이후는 A1 결과와 오너의 계속 결정을 보고 연다.

## 열린 질문

검토 두 차례가 남긴 것이다. 구현을 시작할 때 각 단계의 선행 조건에서 다시 연다.

- **라이브러리 도입 여부.** 후보의 현재 버전과 API를 확인하지 못했고, 비교에 쓸 제스처·초점 요구는 A2a를 시작할 때 정해진다. A2a의 작은 검증에서 정한다.
- **"전체"의 범위와 권한·페이지 포함 비용.** 권한 모델과 목록 API의 실제 한계를 측정하지 않아 기간으로 바꿀 근거가 없다. B를 시작할 때 따로 추정한다.
- **94S-928의 최종 계약.** 세션 사이 관계 계약은 에이전트 네트워크 설계 결론에 달려 있어 이 문서가 확정할 수 없다. C·D는 그 계약 뒤에 다시 설계한다.
- **선택 세션 행이 이전 세션 제목 아래 잠깐 보이는 문제.** 확정된 결함이 아니라 새 구현에서 확인할 실패 조건이다. A1의 수용 기준으로만 둔다.
- **주소 갱신의 반복, 깜박임, 뒤로 가기 동작.** 실행해 확인하지 않았다. A1 테스트와 브라우저 확인 항목으로 넘긴다.
- **시간 범위를 좁혔을 때 종료 수·"다시 정리"·알림이 어느 범위를 세는지.** 시간 범위가 없는 지금은 생기지 않는 문제이고, 도입하는 B에서 함께 푼다.
- **사용자가 거는 필터(에이전트 등).** 도입 여부 자체가 정해지지 않았다. 도입하면 위 "두 뷰가 함께 쓰는 상태"의 조건을 함께 설계한다.
- **세션 사이 경로 재생의 계약.** 메시지 ID, 보내는 쪽·받는 쪽, 답과의 짝, 같은 시각의 순서, 권한상 보이지 않는 구간의 처리가 정해져야 D를 시작할 수 있다.
- **성능 수치.** 이 문서의 어느 숫자도 측정한 값이 아니다. 임계값은 A2a 측정 뒤에 정한다.
- **전환 컨트롤 형태.** 버튼 그룹을 유지하기로 했으나, 탭이나 라디오도 수동 활성화로 쓸 수 있어 접근성 검증에서 문제가 나오면 다시 연다.
