---
title: "저장소 없는 세션"
description: 저장소를 clone하지 않고 빈 작업 공간에서 도는 세션
---

세션은 `repository_id`를 보내면 그 저장소를 clone하고, 빼면 저장소 없이 빈 작업 공간에서 시작할 수 있다. 저장소는 워크스페이스 상한과 에이전트의 GitHub 설정 안이어야 한다. SDK 예제는 [SDK 설치](/getting-started/install#클라이언트-만들기)에서 만든 `werft` 클라이언트를, HTTP API 예제는 서버 주소 `API`와 key `KEY` 셸 변수를 쓴다.

## 저장소 없이 만들기

`repository_id`를 빼고 만든다.

<Tabs groupId="client" persist items={["SDK", "HTTP API"]}>
<Tab>

```ts
const created = await werft.sessions.create({
  agent_release_id: process.env.WERFT_AGENT_RELEASE_ID ?? "",
  message: 'GATE-SPEC {"id":"no-repo","steps":[],"final":"no repository here"}',
});
console.log(created.status);
const session = await werft.sessions.get(created.session_id);
console.log(session.repository_id, session.repository);
```

```text
queued
null null
```

</Tab>
<Tab>

```bash
NOREPO=$(curl -sS "$API/v1/sessions" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg m 'GATE-SPEC {"id":"no-repo","steps":[],"final":"no repository here"}' \
    '{agent_release_id: env.WERFT_AGENT_RELEASE_ID, message: $m}')" | jq -r .session_id)
curl -sS "$API/v1/sessions/$NOREPO" -H "Authorization: Bearer $KEY" | jq -c '{repository_id, repository}'
```

```text
{"repository_id":null,"repository":null}
```

레퍼런스: [`POST /v1/sessions`](/reference/http-api/sessions/createSession)

</Tab>
</Tabs>

저장소가 없으니 push할 곳도 없다. 이 세션의 [push 요청](/approvals/request)은 409 `PUSH_SOURCE_MISSING`이다.

## 에이전트 세션은 저장소 없이 시작한다

[에이전트](/agents/create#세션에-묶기)의 release로 만든 세션에서 `repository_id`를 빼면, GitHub 설정이 있는 에이전트는 저장소 없이 시작한다. 예외가 아니라 에이전트 세션의 기본이다. 에이전트는 허용된 저장소를 `list_repositories`로 보고, 작업이 읽거나 바꾸는 저장소만 `attach_repository`로 붙인다([세션 도중 저장소 붙이기](/integrations/github#세션-도중-저장소-붙이기)). 붙인 저장소는 작업 공간에 git 원격으로 들어오고, 그 저장소에 쓰는 일은 저장소마다 push 요청 한 번씩 [승인](/approvals/request)을 거친다.

저장소가 없는 세션에서 만든 파일 가운데 성과물로 모으려는 것은 작업 공간 루트의 `out/`에 둔다. checkpoint가 그 아래 파일을 성과물로 거둔다. `repository_id`를 보내면 그 저장소로 시작하고, GitHub 설정이 아직 없는 옛 에이전트는 release의 저장소로 시작한다.
