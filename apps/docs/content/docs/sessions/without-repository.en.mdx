---
title: "Sessions without a repository"
description: A session that runs in an empty workspace without cloning a repository
---

A session clones the repository named by `repository_id`, or, left out, can start in an empty workspace with no repository. The repository must be within the workspace ceiling and the agent's GitHub settings. The SDK examples use the `werft` client made in [Install the SDK](/getting-started/install#create-a-client), and the HTTP API examples use the shell variables `API` (the server address) and `KEY` (the key).

## Create without a repository

Create the session without `repository_id`.

<Tabs groupId="client" persist items={["SDK", "HTTP API"]}>
<Tab>

```ts
const created = await werft.sessions.create({
  agent_release_id: process.env.WERFT_AGENT_RELEASE_ID ?? "",
  message: 'GATE-SPEC {"id":"no-repo","steps":[],"final":"no repository here"}',
});
console.log(created.status);
const session = await werft.sessions.get(created.session_id);
console.log(session.repository_id, session.repository);
```

```text
queued
null null
```

</Tab>
<Tab>

```bash
NOREPO=$(curl -sS "$API/v1/sessions" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg m 'GATE-SPEC {"id":"no-repo","steps":[],"final":"no repository here"}' \
    '{agent_release_id: env.WERFT_AGENT_RELEASE_ID, message: $m}')" | jq -r .session_id)
curl -sS "$API/v1/sessions/$NOREPO" -H "Authorization: Bearer $KEY" | jq -c '{repository_id, repository}'
```

```text
{"repository_id":null,"repository":null}
```

Reference: [`POST /v1/sessions`](/reference/http-api/sessions/createSession)

</Tab>
</Tabs>

With no repository there is nowhere to push. A [push request](/approvals/request) for this session is 409 `PUSH_SOURCE_MISSING`.

## An agent session starts without a repository

When you omit `repository_id` on a session made from an [agent](/agents/create#bind-to-a-session) release, an agent with GitHub settings starts without a repository. That is the default for agent sessions, not an exception. The agent sees the allowed repositories with `list_repositories` and attaches only the ones the task reads or changes with `attach_repository` ([Attaching a repository mid-session](/integrations/github#attaching-a-repository-mid-session)). An attached repository enters the workspace as a git remote, and writing to it goes through [approval](/approvals/request) with one push request per repository.

In a session without a repository, put the files you want collected as outputs in `out/` at the workspace root; a checkpoint collects the files under it. If you send `repository_id`, the session starts on that repository, and an older agent with no GitHub settings yet starts on its release's repository.
