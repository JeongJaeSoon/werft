---
title: "メンバーの招待"
description: 招待リンクを作成して渡し、受け取った人がパスワードまたはログインプロバイダーで承諾する
---

ワークスペースに人を迎え入れる方法は招待リンクです。owner または admin が、受け取る人のメールアドレスとロールでリンクを作成し、直接渡します。受け取った人がリンクを開いて承諾すると、メンバーになります。プラットフォームはメールを送信しません。

## 招待リンクを作成する

Web コンソールの **メンバー** 画面で **メンバーを招待** をクリックし、メールアドレスとロールを決めて **招待リンクを作成** をクリックします。Web ログインの cookie で `POST /v1/invites`（`email`、`role`）を呼び出しても同じです。

- 招待できるのは owner と admin です。member が呼び出すと 403 `FORBIDDEN` です。
- ロールの一覧には、いま招待できるロールだけが表示されます。admin は owner として招待できません（403 `OWNER_PROTECTED`）。
- リンクは作成したその時に一度だけ表示されます。サーバーはトークンのハッシュだけを保存します。コピーせずにウィンドウを閉じると二度と表示できないため、その場合は招待を取り消して作り直します。
- リンクは 7 日間使えます。有効期限はリンクの下と、招待の一覧に表示されます。期限を過ぎた招待も一覧に **期限切れ** として残ります。
- アドレスは前後の空白を除き、小文字にして比較します。同じアドレスにもう一度招待すると前の招待は取り消され、新しいリンクだけが使えます。
- すでにメンバーのアドレスは 409 `ALREADY_EXISTS`（`reason_code: already_member`）です。アカウントが停止されたメンバーも同じです。
- 無効化したメンバーは、一覧から再び有効にします。そのアドレスに招待しようとすると、コンソールもそう案内します。パスワードのあるアカウントは、招待し直してパスワードで承諾してもメンバーシップが再び有効になりますが、プロバイダーのボタンでは承諾できません（409）。プロバイダーでだけログインしていたアカウントは、招待では戻れません。パスワードがないためパスワードでの承諾は 401 で、プロバイダーで承諾しても 409 です。

招待を作成するたびに `invite_member` の receipt が残ります。

## 招待を取り消す

保留中の招待の横にある **取り消し** をクリックします。API では `DELETE /v1/invites/{id}` で、204 を返します。

| 状況 | 応答 |
| --- | --- |
| 保留中の招待 | 204。そのリンクではもう承諾できません（410） |
| すでに取り消した招待 | 204。何も変わりません |
| すでに承諾された招待 | 409 `INVITE_USED` |
| 存在しない id | 404 |

取り消すと `revoke_invite` の receipt が残ります。

## パスワードで承諾する

受け取った人がリンクを開くと **招待を承諾** 画面が表示されます。まず、招待されたメールアドレスで使っているアカウントがあるかを選びます。

- **いいえ、初めてです**: 新しいパスワード（12 文字以上）と名前を入力します。そのメールアドレスでアカウントが作られ、招待のロールで参加します。名前を空にするとメールアドレスから決まります。
- **はい、アカウントがあります**: いま使っているパスワードを入力します。パスワードは変わりません。パスワードが違うと 401 で、招待は使われません。

この選択は画面の入力欄を変えるだけです。サーバーは選んだ答えではなく、招待されたメールアドレスのアカウントがあるかどうかで決めます。そのアカウントがすでにあれば、**いいえ、初めてです** を選んでいても、入力したパスワードをそのアカウントの現在のパスワードとして確認し（違うと 401）、名前は使いません。

承諾するとすぐにログインします。招待トークンは一度だけ使えます。

## ログインプロバイダーで承諾する

有効な[ログインプロバイダー](/run-server/self-hosting/sso)があると、承諾画面の **パスワードなしで参加** の下にプロバイダーごとのボタン（例: **Keycloak で参加**）も表示されます。インストールでパスワードログインがオフになっている場合は、プロバイダーのボタンだけが表示されます。

ボタンをクリックすると、プロバイダーのログイン画面に移動してから戻ってきます。まだどのユーザーにも接続されていないアカウントをプロバイダーが保証すると、アカウントが作られて招待が使われます。アカウントのメールアドレスはプロバイダーが送ったアドレスではなく招待されたアドレスで、ロールは招待のロールです。プロバイダーで作ったアカウントにはパスワードがありません。

プロバイダー側で拒否されると、コールバック画面が理由を伝えます。どの場合も招待は使われないため、受け取ったリンクをもう一度開いてやり直せます。

| 画面に表示されるもの | 理由 |
| --- | --- |
| このアカウントでは参加できません | プロバイダーの許可ドメイン外のアカウントです |
| このログインプロバイダーでは現在参加できません | そのプロバイダーが削除されたか、オフになりました |
| 参加を始めたアドレスと戻ってきたアドレスが異なります | リンクを開いたアドレスと、プロバイダーが戻したアドレスが異なります。またはプロバイダーの画面に 10 分を超えてとどまり、参加の流れが終わりました。コンソールの正式なアドレスでリンクを開き直します |
| このプロバイダーのアカウントは、すでに別のユーザーに接続されています | 409 `ALREADY_EXISTS`。そのプロバイダーのアカウントで、すでに別のユーザーがログインしています |
| このプロバイダーのアカウントを、同じメールアドレスのコンソールアカウントに自動で接続できません | 409 `LOGIN_LINK_REQUIRED`。招待されたメールアドレスのアカウントがすでにあり、プロバイダーがそのアドレスを証明しなかった（別のアドレス、またはアドレスなし）、そのアカウントが停止中か無効化されたメンバーである、またはそのアカウントに同じプロバイダーの別のアカウントがすでに接続されている、のいずれかです |
| 参加できませんでした | 401。プロバイダーが `email_verified: false` としたアカウントである（設定に関係なく）、検証済みメールを求めるプロバイダーからアドレスまたは `email_verified: true` を受け取れなかった、プロバイダーの応答を検証できなかった、またはその間に招待が取り消された・期限切れになった、のいずれかです。サーバーはどれかを伝えません |
| 参加が完了しませんでした | プロバイダーの画面で中断しました |

許可ドメインと検証済みメールのルール、招待アドレスのアカウントがすでにある場合の動作は [SSO ログインの構成](/run-server/self-hosting/sso)にあります。

## 使えないリンク

| 画面 | 応答 | 理由 |
| --- | --- | --- |
| この招待は使用できません | 410 `INVITE_EXPIRED` | 取り消された、同じアドレスへの新しい招待に置き換えられた、または 7 日が過ぎました。存在しないトークンにも同じように応答します |
| この招待は承諾済みです | 409 `INVITE_USED` | このリンクですでに承諾しました。ログイン画面からログインします |
| すでにこのワークスペースのメンバーです | — | いまログインしているアカウントがすでにメンバーです。別のアカウントで承諾するには、ログアウトしてリンクを開き直します |

必要なら、招待した人に新しいリンクを頼みます。承諾すると `accept_invite` の receipt が残ります。
