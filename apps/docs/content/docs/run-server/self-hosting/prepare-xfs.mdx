## 무엇을 하게 되나

Docker data-root를 XFS prjquota 위에 두어 workspace byte·inode 상한을 강제한다. 기존 디스크·이미지·Docker 데이터는 보존한다. 릴리스 번들의 `scripts/prepare-xfs.sh`가 사전 검사부터 확인까지 한 번에 하고, 한 단계가 실패하면 그 앞의 단계를 되돌린다.

## 준비물

운영에 사용할 Linux 서버(먼저 별도 시험 서버에서 검증)에서 실행한다. root 권한, systemd로 실행 중인 Docker Engine, xfsprogs·rsync, 원본 전체를 보관할 공간, 유지보수 시간이 필요하다. 스크립트는 [릴리스 번들](/run-server/self-hosting/single-server#릴리스-번들로-받기)을 푼 디렉터리의 `scripts/prepare-xfs.sh`다. 저장소 checkout에도 같은 경로에 있다. Docker Desktop은 이 설치 경로를 지원하지 않는다.

xfsprogs와 rsync는 배포판의 패키지 관리자로 설치한다. apt를 쓰는 배포판에서는 다음과 같다.

```bash
sudo apt-get install -y xfsprogs rsync
```

## 단계

### 1. 현재 상태 확인

```bash
findmnt -no FSTYPE,OPTIONS -T "$(docker info -f '{{.DockerRootDir}}')"
P="quota-probe-$(date +%s)"; docker volume create --driver local --opt size=64m "$P" && docker volume rm "$P"
```

XFS와 prjquota가 이미 적용됐고 probe가 성공하면 이 페이지의 나머지는 건너뛴다. 이 상태에서는 스크립트도 아무것도 바꾸지 않고 끝난다. quota probe가 실패하면 원인을 해결할 때까지 deploy하지 않는다.

### 2. dry-run으로 사전 검사

번들 디렉터리에서 실행한다.

```bash
sudo bash scripts/prepare-xfs.sh --dry-run
```

dry-run은 사전 검사만 하고 실행할 단계를 출력한다. 호스트는 바꾸지 않는다. 사전 검사는 다음을 본다.

- root로 실행했고 `mkfs.xfs`, `rsync`, `findmnt` 같은 필요한 명령이 있다.
- Docker가 systemd로 실행 중이고 live-restore가 꺼져 있으며 data-root가 `/var/lib/docker`다. live-restore가 켜져 있으면 Docker를 멈춰도 컨테이너가 계속 쓰므로 거부한다. 그 경로는 symlink나 mount 지점이 아니다.
- `/var/lib/docker.xfs.img`, `/var/lib/docker.old`, `/etc/fstab.before-prepare-xfs`가 없고, `/etc/fstab`에 `/var/lib/docker` 항목이 없다. 지금의 `/etc/fstab`에서 `findmnt --verify`가 오류를 찾지 않는다.
- `/var/lib`에 이미지 크기만큼 여유가 있다.
- 커널이 XFS를 지원하고, 임시 512M 이미지를 loop와 prjquota로 시험 mount할 수 있다. 시험 이미지는 검사 뒤 지운다.

검사 하나가 실패하면 이유와 `nothing was changed`를 출력하고 종료 코드 1로 끝난다. loop 장치나 XFS 지원이 없는 서버(컨테이너형 서버 등)는 Docker를 멈추기 전에 여기서 멈춘다.

### 3. 디스크 준비 실행

```bash
sudo bash scripts/prepare-xfs.sh
```

스크립트는 같은 사전 검사를 다시 한 뒤 다음을 차례로 실행한다. Docker 중지, `/var/lib/docker`를 `/var/lib/docker.old`로 이동, 60G sparse 이미지 `/var/lib/docker.xfs.img` 생성과 `mkfs.xfs`, `loop,prjquota` mount, 원본 복사(`rsync -aHAX`), `/etc/fstab`을 `/etc/fstab.before-prepare-xfs`로 백업한 뒤 아래 항목 추가와 `findmnt --verify`, Docker 시작, data-root·mount·quota probe 확인.

```text
/var/lib/docker.xfs.img /var/lib/docker xfs loop,prjquota 0 0
```

스크립트가 이 항목을 `/etc/fstab`에 직접 덧붙이므로 편집기로 고칠 필요가 없다. 이 단계의 `findmnt --verify`는 종료 코드 0이면서 경고 2개를 낼 수 있고, 둘 다 정상이다. `non-bind mount source /var/lib/docker.xfs.img is a directory or regular file`은 loop로 mount하는 source가 일반 파일이라는 알림이다. `your fstab has been modified, but systemd still uses the old version`은 systemd가 바뀐 fstab을 아직 다시 읽지 않아서 나오며, 스크립트가 바로 다음에 `systemctl daemon-reload`를 실행한다.

이미지 크기는 `--size`로 바꾼다. 값은 정수 GB다(예: `--size 100G`). 60G는 `/var/lib/docker`에 들어가는 volume과 컨테이너 로그가 나눠 쓰는 합계 천장이다. 파일시스템 metadata도 공간을 쓰므로 실제 데이터 여유는 이보다 작다. Docker 29 이상을 새로 설치해 containerd image store(기본값)를 쓰면 이미지와 컨테이너 층은 `/var/lib/containerd`에 쌓여 XFS 이미지 밖(보통 루트 디스크)을 쓴다. 그 여유는 따로 확인한다. XFS 이미지는 sparse 파일이지만 호스트에 그만큼의 여유가 있어야 한다.

한 단계가 실패하면 스크립트가 그 앞의 단계를 거꾸로 되돌린다. fstab을 백업본으로 복원하고, unmount하고, 만든 mount 지점과 이미지를 지우고, 원본을 `/var/lib/docker`로 되돌린 뒤 Docker를 다시 시작한다. Docker가 새 이미지에서 이미 시작됐다면 그동안 쓴 내용이 이미지에 있으므로 이미지는 지우지 않고 그 경로를 출력한다.

| 종료 코드 | 뜻 |
| --- | --- |
| 0 | 준비가 끝났다. 또는 이미 준비돼 있어 바꾼 것이 없다 |
| 1 | 사전 검사가 거부했다. 바꾼 것이 없다 |
| 2 | 인자가 잘못됐다 |
| 3 | 한 단계가 실패했고 모두 되돌렸다. Docker는 원래 data-root로 다시 실행 중이다 |
| 4 | 한 단계가 실패했고 되돌리기도 일부 실패했다. 출력이 남은 상태를 적는다 |

## 확인

스크립트가 마지막에 data-root, mount 옵션, quota probe를 확인한다. 1단계의 명령을 다시 실행하면 `xfs`·`prjquota`와 probe 성공을 직접 볼 수 있다. `df -h`, `df -i`, `xfs_quota -x -c 'report -p'`로 여유를 확인한다.

## 자주 막히는 곳

- `already exists`로 거부되면 앞선 실행이나 수동 작업이 남긴 경로다. 내용을 조사한다. 이미지나 `/var/lib/docker.old`를 크기 변경이나 mkfs로 재사용하지 않는다.
- 되돌린 뒤 다시 실행했는데 `/var/lib/docker.xfs.img`나 `/etc/fstab.before-prepare-xfs`가 이미 있다고 거부되면, 앞선 되돌리기가 남긴 파일이다. Docker가 새 이미지에서 이미 돌았다면 스크립트도 이미지를 지우지 않는다. 이미지에 보존할 데이터가 없음을 확인하고, unmount와 fstab 복원·`daemon-reload`가 끝나 `/var/lib/docker`가 원본으로 돌아온 뒤에만 `sudo rm /var/lib/docker.xfs.img /etc/fstab.before-prepare-xfs`로 지운다. `/var/lib/docker.old`가 남아 있으면 원본이므로 지우지 말고 먼저 되돌린다.
- `the trial XFS loop mount`로 거부되면 이 호스트에서는 loop 장치나 XFS project quota를 쓸 수 없다. 다른 서버를 쓰거나, Docker data-root용 XFS 디스크를 따로 붙이는 이전 계획을 세운다.
- 종료 코드 4이고 data-root가 제자리에 돌아오지 않았으면 스크립트는 Docker를 멈춘 채 둔다. 이 상태에서 Docker를 시작하면 빈 data-root를 사용하므로, 출력에 적힌 남은 상태를 [되돌리기](#되돌리기)의 순서로 정리한 뒤 시작한다.

## 되돌리기

Docker를 새 XFS에서 다시 시작한 뒤 만든 컨테이너·volume·데이터는 `/var/lib/docker.old`에 없다. 원본 디렉터리로 되돌리면 그 변경을 잃으므로 먼저 새 데이터를 별도로 보존하고 복구할 대상을 결정한다. sparse 이미지는 삭제한 데이터만큼 자동으로 줄어들지 않으므로 호스트 파일시스템 여유도 감시한다.

Docker와 socket을 중지한다. 새 XFS가 mount돼 있으면 사용 중인 컨테이너가 없음을 확인한 뒤 unmount하고, 추가된 fstab 항목을 스크립트가 남긴 `/etc/fstab.before-prepare-xfs`와 대조해 되돌린 뒤 `sudo systemctl daemon-reload`로 systemd가 복원된 fstab을 다시 읽게 한다. `/var/lib/docker.old`가 원본이다. 원래 경로가 비어 있음을 확인한 뒤 원본을 되돌리고 Docker를 시작한다. 새 이미지나 원본을 삭제하지 말고 기존 컨테이너·volume 목록이 맞는지 확인한다.

원래 데이터 디렉터리가 있었던 설치에서 unmount와 fstab 복원이 끝난 뒤에는 비어 있는 mount 지점만 `sudo rmdir /var/lib/docker`로 제거하고 `sudo mv /var/lib/docker.old /var/lib/docker`로 되돌린다. rmdir가 실패하면 안의 데이터를 지우지 말고 조사한다. 원본이 없었던 새 설치에는 이 이동을 실행하지 않는다.
