## 무엇을 하게 되나

설치의 모델 연결과 그 연결로 쓸 수 있는 모델 목록을 구성하고, 그 연결로 release한 에이전트의 세션 한 turn으로 실제 호출을 확인한다. 모델 자격 증명은 사용자 API key와 다르다.

## 준비물

owner 로그인, 사용할 모델의 key 또는 사설 모델 endpoint, 세션에서 접근할 저장소가 필요하다. 비용 상한과 [설정 계약](/run-server/self-hosting/reference/configuration)을 확인한다.

## 단계

<a id="1-콘솔-연결과-프로필" />

### 1. 콘솔 연결과 모델 목록

세션은 에이전트 release가 고른 모델 연결로 모델을 부른다. 연결에는 key와 사용할 모델 목록이 있어야 한다. owner로 로그인한 상태에서 다음 순서로 한다.

1. **설정 > 에이전트 연결 > 모델 연결**에서 **연결 추가**를 누른다. 종류는 `anthropic`, 주소는 기본값(`https://api.anthropic.com`)을 두고, Anthropic key를 붙여 넣어 **만들기**를 누른다. key를 8자 이상 넣기 전에는 **만들기**가 꺼져 있다. 키는 DB에 봉인돼 저장되고, 화면에는 끝 네 글자만 보인다.
2. 만들면 바로 **사용할 모델** 창이 열리고, 서버가 그 key로 공급자의 모델 목록(`GET /v1/models`)을 읽어 온다. 창에는 연결 id와 주소가 보인다. 쓸 모델(예: `claude-sonnet-5`)에 체크하고 **모델 저장**을 누른다. 나중에 바꿀 때는 같은 행 끝의 ⋯ 메뉴에서 **모델**을 고르고, **목록 새로고침**으로 다시 읽는다. 저장한 모델은 64개까지다.
   - OpenAI 연결에서는 임베딩·음성·이미지처럼 에이전트가 쓰지 않는 모델을 목록에서 뺀다. LiteLLM은 프록시가 돌려준 목록을 그대로 보인다.
   - 저장된 모델을 공급자가 더는 알려 주지 않으면 체크된 채 **목록에 없음**으로 표시된다. 저절로 빠지지 않으며, 체크를 풀고 저장해야 빠진다.
   - 서버는 key를 egress 자격 증명 허용 목록(`EGRESS_CREDENTIAL_ALLOWLIST`, 사설 서버는 `EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST`)에 있는 호스트에만 보낸다. 허용 목록이 비었거나 호스트가 없거나, 공급자가 key를 거절하거나 닿지 않으면 창에 그 이유가 보인다. 목록을 못 읽어도 저장된 목록은 그대로 저장할 수 있다. key와 공급자의 답 본문은 응답과 로그에 남지 않는다.
   - 목록에서 뺀 모델에 다음 판(같은 계열의 더 높은 순위)이 목록에 있으면, 그 모델로 도는 에이전트와 세션은 다음 판으로 옮겨 간다(`model_families`).
3. 에이전트를 만들 때 **릴리스** 단계에서 이 연결을 고른다([만들기](/agents/create)). 이 연결의 새 release는 `auto` 권한 모드로 돈다.

에이전트가 쓸 저장소는 연결에서 고르지 않고, 해당 에이전트의 **GitHub** 탭에서 워크스페이스가 허용한 범위 안에서 고른다. 무엇을 사람에게 묻는지는 [권한](/agents/permissions)에 있다.

키를 넣기 전에 이 연결의 release로 세션을 시작하면 `모델 연결에 쓸 수 있는 키가 없다`는 취지의 오류가 나고, 오류가 1번 화면 경로를 알려 준다. 키를 바꿀 때도 같은 화면에서 그 행의 ⋯ 메뉴에 있는 **API 키 설정**(Bearer 토큰 연결은 **Bearer 토큰 설정**)을 쓴다.

OpenAI 모델을 Codex 엔진으로 쓰려면 같은 화면에서 종류를 `openai_responses`로 고른다. 주소 기본값은 `https://api.openai.com`이고 인증은 API key만 된다. 이 연결의 세션은 Codex worker 이미지로 돈다. 이미지와 proxy 허용 목록(`api.openai.com:443`)은 [설정 레퍼런스](/run-server/self-hosting/reference/configuration)를 따른다.

성과 판정기 Luna(OpenAI Decisions API)가 쓸 연결(종류 `openai_decisions`)은 이 화면에 보이지 않는다. [성과 규칙](/achievements) 화면의 **판정 모델 설정**에서 만들고, 키를 바꾸고, 사용 중지한다. 주소 기본값은 `https://api.openai.com`이고 인증은 API key만 되며, 판정 비용은 늘 따로 센다.

### 2. 설정 문서로 연결 더하기

연결은 [단일 서버 2단계의 설정 문서](/run-server/self-hosting/single-server#2-비밀과-설정-문서)로도 더할 수 있다. 자격 증명은 언제나 DB에 저장된 값만 쓴다. 문서에는 값 대신 `"stored": true`만 적으므로 비밀이 없다. 환경 변수 이름(`value_env`)이나 AWS Secrets Manager id(`secret_id`)를 적은 항목은 가져오기가 400 `invalid_document`로 거절한다. `connections`를 아래처럼 채우고 `models`에 에이전트가 고를 모델을 적은 뒤 [단일 서버 3단계](/run-server/self-hosting/single-server#3-release-입력-생성)에서 settings digest와 release 입력을 다시 생성한다. 이미 설치했다면 [Compose 업그레이드](/run-server/self-hosting/upgrade-compose)로 적용한다. 설정 문서에 `profiles` 항목이 있으면 가져오기가 거절한다.

```json
{
  "connections": {
    "anthropic": {
      "kind": "anthropic",
      "endpoint": "https://api.anthropic.com",
      "auth": { "kind": "api_key", "stored": true },
      "models": ["claude-sonnet-5", "claude-haiku-4-5"]
    }
  }
}
```

이렇게 가져온 연결은 값이 들어올 때까지 `needs_value`(화면에서는 **값 필요**) 상태이고, 그 연결로 release한 세션은 돌지 않는다. **모델 연결**의 해당 행 ⋯ 메뉴에서 **API 키 설정**(Bearer 토큰 연결은 **Bearer 토큰 설정**)을 골라 key를 넣는다. API로는 owner 세션으로 `POST /v1/installation/settings/connections/{id}/credential`을 부른다. 값은 8바이트 이상이어야 하고 제어 문자와 앞뒤 공백이 없어야 한다. 값은 `PLATFORM_SECRET_KEY`로 암호화돼 DB에 저장된다. 그 뒤 설정 문서에 같은 연결이 남아 있어도 가져오기는 DB의 행을 그대로 둔다.

### 3. 설정 문서 가져오기·내보내기

```bash
API_CONTAINER='<api-container-id-from-this-installation>'
docker exec "$API_CONTAINER" bun run apps/control-host/src/api/settings.ts export > settings.json
docker exec -i "$API_CONTAINER" bun run apps/control-host/src/api/settings.ts import --document - --dry-run < settings.json
```

API_CONTAINER는 이 설치의 status와 project label로 확인한다. Kubernetes에서 아래 package script는 설치 버전의 저장소 checkout과 호스트 Bun·kubectl을 필요로 한다. `bun run settings:k8s export`와 `bun run settings:k8s import --document - --dry-run`으로 바꾼다. dry-run의 추가 항목과 오류를 검토한 뒤 같은 명령에서 `--dry-run`을 빼고 가져온다. 기존 DB 행을 파일 내용으로 무조건 덮어쓰는 도구가 아니다. 연결의 `models`와 `model_families`는 새 연결을 더할 때 함께 들어가고, 이미 있는 연결의 목록은 콘솔에서 고친다. 자격 증명은 문서에 `"stored": true`로만 적고 값은 콘솔에서 넣는다.

### 4. 과금 없는 사설 모델

<a id="과금-없는-profile-billing-none" />

### 과금 없는 연결 (`billing: none`)

자체 호스팅 모델(Ollama, 사설망의 LiteLLM 등)은 토큰당 청구가 없다. 가격표에도 없어서 그대로 두면 fallback 최고 단가로 계산되고, 세션 비용 상한과 SDK `maxBudgetUsd`에 걸려 turn이 끊긴다. 이런 연결은 `billing: none`으로 선언한다.

```yaml
kind: litellm
endpoint: http://litellm:4000
billing: none
auth:
  kind: bearer
  stored: true
models:
  - qwen3-coder
```

- 생략하면 `per_token`이다. 가격표·fallback으로 계산한다.
- `none` 연결로 release한 세션의 provider 호출은 응답이 어떤 model 이름을 대든 비용 0, ledger `priced_by=unmetered`로 적힌다. 토큰은 그대로 적힌다. 세션 비용이 늘지 않으므로 비용 상한 판정 네 곳(egress 인가, `nextInput`, 메시지 접수, 엔진)에 걸리지 않는다.
- claim의 `remaining_budget_usd`는 `null`이고 worker는 SDK에 `maxBudgetUsd`를 넘기지 않는다. SDK는 모르는 model을 자체 추정 단가로 계산해 예산에서 turn을 끊기 때문이다. 묶을 예산이 없으므로 `/clear` 등으로 SDK의 비용 집계가 다시 시작돼도 worker는 drain하지 않는다.
- `GET /v1/sessions/{id}/usage`는 `cost.kind: "unmetered"`로 답한다. `amount_usd`는 `"0.000000"`이다. 이 세션에는 비용 상한이 적용되지 않으므로 `cost_limit_usd`는 `null`이다. 상한 도달 안내(`attention.reason`)에도 달러 상한은 나오지 않는다. `budget_exceeded`는 토큰 상한에 닿았을 때만 `true`가 된다.
- 과금 여부는 세션을 만들 때 세션 행(`sessions.unmetered`)에 고정된다. 가격·claim 예산·usage 표시는 이 값을 읽는다. 연결이 가리키는 곳(endpoint·종류·`billing`·자격 증명 출처)은 바뀌지 않는다. 다른 값이 필요하면 새 id로 연결을 더하고 에이전트를 다시 release한다.
- 세션 토큰 상한과 시간·동시성 상한(턴 시간, `EXECUTION_SLOT_LIMIT`, 대기 메시지)은 그대로 걸린다([웹에서 정하는 실행 한도](/run-server/self-hosting/reference/configuration#웹에서-정하는-실행-한도)). `unmetered` 행의 토큰도 `sessions.provider_tokens`에 더해진다.
- API는 endpoint host가 사설 주소(10/8, 172.16/12, 192.168/16, 100.64/10, 127/8, `::1`, fc00::/7. link-local 주소와 `::ffff:10.0.0.1`처럼 IPv6 안에 쓴 IPv4는 사설로 보지 않는다)이거나 공개 DNS에 없는 이름(점 없는 compose 서비스 이름, `localhost`, `.internal`·`.local`·`.localhost`·`.lan`·`.home.arpa`)일 때만 `none`을 받는다. egress proxy 쪽에서는 그 host를 `EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST`에 둔다.
- 사설 주소는 필요조건일 뿐이다. 사설망의 LiteLLM도 유료 upstream을 대리할 수 있다. `none` 선언이 맞는지는 운영자가 책임진다. 잘못 선언하면 유료 호출이 비용 상한 없이 나간다. 세션 토큰 상한을 정해 두면 그때도 세션당 토큰은 묶인다. Datadog `werft.provider.unmetered_tokens_1h`(최근 1시간 `unmetered` 행 토큰 합)와 provider 콘솔의 사용량을 같이 본다.

활성화 전에 [업그레이드 게이트](/run-server/self-hosting/upgrade-compose#실행-전-게이트)를 충족해야 한다.

## 확인

이 연결로 release한 에이전트에서 세션을 만들고 turn이 completed인지 확인한다. ready 200은 모델 key나 호출 성공을 검사하지 않는다. 설정 문서로 가져온 연결에 key를 넣은 뒤에는 상태가 `needs_value`에서 벗어났는지와 새 호출을 확인한다.

## 자주 막히는 곳

모델 key 없음 오류는 연결 화면의 경로를 확인한다. 모델 목록이 비어 있으면 그 연결로는 release를 만들 수 없다. 사설 endpoint라는 이유만으로 billing:none이 안전해지는 것은 아니다. 유료 upstream을 대리하는 모델을 none으로 선언하면 비용 상한 없이 호출된다.

## 되돌리기

연결을 끄면 그 연결의 release로 도는 세션이 멈춘다(`CATALOG_MISMATCH`). 끄기 전에 화면의 영향 수(에이전트·세션)를 확인하고, 에이전트를 다른 연결로 다시 release한다. 콘솔에 저장한 key를 폐기할 때는 provider 쪽 권한도 함께 정리한다.
