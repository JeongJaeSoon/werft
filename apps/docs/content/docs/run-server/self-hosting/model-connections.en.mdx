## What you will do

Configure the installation's model connections and the models each one offers, then verify a real model call with one session turn of an agent released on that connection. Model credentials are separate from user API keys.

<a id="준비물" />
## Before you begin

You need an owner login, a key for the model or a private model endpoint, and the repository sessions will access. Review cost limits and the [configuration contract](/run-server/self-hosting/reference/configuration).

<a id="단계" />
## Steps

<a id="1-콘솔-연결과-프로필" />
<a id="1-콘솔-연결과-모델-목록" />
### 1. Console connections and model lists

A session calls its model through the model connection its agent release chose. A connection needs a key and the list of models agents may pick. Signed in as owner:

1. In **Settings > Agent connections > Model connections**, choose **Add connection**. Use kind `anthropic`, keep the default address (`https://api.anthropic.com`), paste the Anthropic key, and save. The key is sealed in the database; the console shows only its last four characters.
2. On the same row, under **Models**, enter the model names agents may use (for example `claude-sonnet-5`) and save. When a model taken off the list has a later version of its series on the list, agents and sessions on it move to that one (`model_families`).
3. Under **Auto mode**, say whether the auto-mode classifier works on the connection. With `supported` (or an Anthropic connection nobody judged), new releases run the `auto` permission mode; otherwise `default`.
4. When you create an agent, choose this connection in the **Release** step ([Create](/agents/create)).

Choose repositories in the agent's **GitHub** tab, within the workspace's allowed scope, not on the connection. What to ask about and block is set by the workspace's and the agent's run rules ([Permissions](/agents/permissions)).

Starting a session on a release of this connection before providing a key produces an error indicating no key is available for the model connection. The error points to the console path in step 1. Use **Replace value** on the same screen to rotate the key.

<a id="2-환경-변수-대안" />
### 2. Environment-variable alternative

To keep the key in the server env file instead of the database, set `ANTHROPIC_API_KEY` in `/etc/werft/test-ops.env`, and name the connection by environment variable in the [settings document from single-server step 2](/run-server/self-hosting/single-server#2-비밀과-설정-문서). The document contains names only, never values. Fill `connections` as below, list the models agents may pick in `models`, then regenerate settings digest and release input in [single-server step 3](/run-server/self-hosting/single-server#3-release-입력-생성). For existing installations, apply with the [Compose upgrade](/run-server/self-hosting/upgrade-compose). An import refuses a settings document that still has a `profiles` entry.

```json
{
  "connections": {
    "anthropic": {
      "kind": "anthropic",
      "endpoint": "https://api.anthropic.com",
      "auth": { "kind": "api_key", "value_env": "ANTHROPIC_API_KEY" },
      "models": ["claude-sonnet-5", "claude-haiku-4-5"]
    }
  }
}
```

You can later move this connection to console-managed credentials. On its **Model connections** row, choose **Enter key on screen** and paste the key again; the same connection then uses the stored key. The server does not read and migrate the env value: a person re-enters it. After the move, an import that still names the same connection leaves the database row unchanged.

On Kubernetes, if the Secret's model key is no longer used, remove its name from `secrets.catalogEnv`. Keep names you still need, such as a fixed bootstrap token. The list replaces the whole set, so keep it aligned with the Secret's keys.

<a id="3-설정-문서-가져오기내보내기" />
### 3. Import and export settings

```bash
API_CONTAINER='<api-container-id-from-this-installation>'
docker exec "$API_CONTAINER" bun run apps/control-host/src/api/settings.ts export > settings.json
docker exec -i "$API_CONTAINER" bun run apps/control-host/src/api/settings.ts import --document - --dry-run < settings.json
```

Identify API_CONTAINER from this installation's status and project label. On Kubernetes, the package scripts below require a checkout matching the installed version and host Bun/kubectl. Substitute `bun run settings:k8s export` and `bun run settings:k8s import --document - --dry-run`. Review additions and errors from dry-run, then remove `--dry-run` from the same command to import. This tool does not unconditionally overwrite existing database rows with file contents. A connection's `models` and `model_families` go in when the connection is added; change the list of an existing connection in the console. Reference credential environment-variable names instead of values in the document.

<a id="4-과금-없는-사설-모델" />
### 4. Private models without per-token billing

<a id="과금-없는-profile-billing-none" />
<a id="과금-없는-연결-billing-none" />
### Unmetered connections (`billing: none`)

Self-hosted models (Ollama, private-network LiteLLM, etc.) have no per-token charge. If absent from the price table and left unchanged, they use the highest fallback rate and hit `SESSION_COST_LIMIT_USD` and SDK `maxBudgetUsd`, cutting turns. Declare such a connection with `billing: none`.

```yaml
kind: litellm
endpoint: http://litellm:4000
billing: none
auth:
  kind: bearer
  value_env: LITELLM_MASTER_KEY
models:
  - qwen3-coder
```

- If omitted, it is `per_token`, priced from the price table or fallback.
- Provider calls from a session released on a `none` connection record cost 0 and ledger `priced_by=unmetered`, regardless of the model name in the response. Tokens are still recorded. Session cost does not grow, so none of the four cost-limit checks (egress authorization, `nextInput`, message acceptance, engine) stops it.
- The claim's `remaining_budget_usd` is `null`, and the worker passes no `maxBudgetUsd` to the SDK, because the SDK prices an unknown model at its own estimate and cuts the turn on that budget. With no budget to hold, the worker does not drain when the SDK's cost tally restarts (for example after `/clear`).
- `GET /v1/sessions/{id}/usage` answers `cost.kind: "unmetered"` with `amount_usd` `"0.000000"`. No cost limit applies to the session, so `cost_limit_usd` is `null`, and the limit notice (`attention.reason`) names no dollar limit. `budget_exceeded` becomes `true` only on the token limit.
- Billing mode is fixed at session creation in `sessions.unmetered`; pricing, claim budgets and usage displays read that value. What a connection points at (endpoint, kind, `billing`, credential source) never changes: when you need other values, add a connection under a new id and release the agent again.
- The token limit (`SESSION_TOKEN_LIMIT`) and time and concurrency limits (`MAX_TURN_SECONDS`, `EXECUTION_SLOT_LIMIT`, `QUEUED_INPUT_LIMIT_PER_SESSION`) still apply. Tokens of `unmetered` rows are added to `sessions.provider_tokens` too.
- The API accepts `none` only when the endpoint host is a private address (10/8, 172.16/12, 192.168/16, 100.64/10, 127/8, 169.254/16, `::1`, fc00::/7, fe80::/10) or a name public DNS does not serve (a compose service name without a dot, `localhost`, `.internal`, `.local`, `.localhost`, `.lan`, `.home.arpa`). On the egress proxy, list that host in `EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST`.
- A private address is necessary but not sufficient: a private-network LiteLLM can still front a paid upstream. The operator is responsible for the `none` declaration; a wrong one sends paid calls with no cost limit. Setting `SESSION_TOKEN_LIMIT` still bounds tokens per session. Watch Datadog `werft.provider.unmetered_tokens_1h` (tokens of `unmetered` rows over the last hour) alongside the provider console's usage.

Meet the [upgrade gate](/run-server/self-hosting/upgrade-compose#실행-전-게이트) before enabling it.

<a id="확인" />
## Verify

Create a session on an agent released on this connection and confirm a turn completes. ready 200 does not check model keys or successful calls. After moving the environment-variable path to the console, confirm new calls and key rotation work.

<a id="자주-막히는-곳" />
## Troubleshooting

For a missing model key error, check the connection screen path. A connection with an empty model list cannot be released on. A private endpoint alone does not make billing:none safe; declaring a model that fronts a paid upstream as none sends calls with no cost limit.

<a id="되돌리기" />
## Roll back

Disabling a connection stops the sessions running on releases of it (`CATALOG_MISMATCH`). Before disabling, check the impact counts (agents, sessions) on the screen and release those agents on another connection. When discarding a key stored in the console, also clean up its permissions on the provider side.
