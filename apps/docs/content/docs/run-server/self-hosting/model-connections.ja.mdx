## 作業内容

設置のモデル接続と、その接続で使えるモデル一覧を構成し、その接続でリリースしたエージェントのセッションの一つの turn で実際の呼び出しを確認します。モデルの資格情報はユーザーの API キーとは別です。

<a id="준비물" />
## 準備

オーナーのログイン、使うモデルのキーまたはプライベートなモデルの endpoint、セッションがアクセスするリポジトリが必要です。費用の上限と[設定の契約](/run-server/self-hosting/reference/configuration)を確認します。

## 手順

<a id="1-콘솔-연결과-프로필" />
<a id="1-콘솔-연결과-모델-목록" />
### 1. コンソールの接続とモデル一覧

セッションは、エージェントのリリースが選んだモデル接続でモデルを呼びます。接続にはキーと、使用するモデルの一覧が必要です。オーナーでログインした状態で次の順に行います。

1. **設定 > エージェントの接続 > モデル接続**で**接続を追加**を押します。種類は `anthropic`、アドレスは既定値（`https://api.anthropic.com`）のままにし、Anthropic のキーを貼り付けて**作成**を押します。キーを 8 文字以上入れるまで**作成**は押せません。キーは DB に封印して保存され、画面には末尾 4 文字だけが表示されます。
2. 作成するとすぐに**使用するモデル**のダイアログが開き、サーバーがそのキーでプロバイダーのモデル一覧（`GET /v1/models`）を読み込みます。ダイアログには接続の id とアドレスが表示されます。使うモデル（例: `claude-sonnet-5`）にチェックを入れて**モデルを保存**を押します。あとで変えるときは同じ行の端にある ⋯ メニューから**モデル**を選び、**一覧を更新**で読み直します。保存できるモデルは 64 件までです。
   - OpenAI の接続では、埋め込み・音声・画像など、エージェントが使わないモデルを一覧から外します。LiteLLM はプロキシが返した一覧をそのまま示します。
   - 保存済みのモデルをプロバイダーがもう示さなければ、チェックされたまま**一覧にない**と表示されます。自動では外れず、チェックを外して保存したときだけ外れます。
   - サーバーは、egress 認証情報の許可リスト（`EGRESS_CREDENTIAL_ALLOWLIST`、プライベートなサーバーは `EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST`）にあるホストにだけキーを送ります。許可リストが空のとき、ホストが載っていないとき、プロバイダーがキーを拒否したり届かなかったりしたときは、その理由がダイアログに出ます。一覧を読めなくても、保存済みの一覧はそのまま保存できます。キーとプロバイダーの答えの本文は、応答にもログにも残りません。
   - 一覧から外したモデルに、同じ系列の次の版が一覧にあれば、そのモデルで動くエージェントとセッションは次の版へ移ります（`model_families`）。
3. エージェントを作るとき、**リリース**ステップでこの接続を選びます（[作成](/agents/create)）。この接続のリリースは `auto` の権限モードで動きます。

エージェントが使うリポジトリは接続では選ばず、そのエージェントの **GitHub** タブで、ワークスペースが許可した範囲から選びます。何を人に確認するかは[権限](/agents/permissions)にあります。

キーを入れる前にこの接続のリリースでセッションを始めると、「モデル接続に使えるキーがない」という趣旨のエラーになり、エラーが手順 1 の画面の場所を教えます。キーを変えるときも同じ画面で、その行の ⋯ メニューにある**API キーを設定**（Bearer トークンの接続では**Bearer トークンを設定**）を使います。

OpenAI のモデルを Codex エンジンで使うには、同じ画面で種類に `openai_responses` を選びます。アドレスの既定値は `https://api.openai.com` で、認証は API キーのみです。この接続のセッションは Codex の worker イメージで動きます。イメージと proxy の許可リスト（`api.openai.com:443`）は[設定リファレンス](/run-server/self-hosting/reference/configuration)に従います。

成果判定器 Luna（OpenAI Decisions API）が使う接続（種類 `openai_decisions`）はこの画面には表示されません。[成果ルール](/achievements)画面の**判定モデルを設定**で作成し、キーの変更や使用停止もそこで行います。アドレスの既定値は `https://api.openai.com` で、認証は API キーのみ、判定の費用は常に別に数えます。

<a id="2-설정-문서로-연결-더하기" />
### 2. 設定文書で接続を加える

接続は[単一サーバーの手順 2 の設定文書](/run-server/self-hosting/single-server#2-비밀과-설정-문서)でも加えられます。資格情報は常に DB に保存された値だけを使います。文書には値の代わりに `"stored": true` だけを書くので秘密はありません。環境変数名（`value_env`）や AWS Secrets Manager の id（`secret_id`）を書いた項目は、import が 400 `invalid_document` で拒否します。`connections` を次のように埋め、`models` にエージェントが選ぶモデルを書いたら、[単一サーバーの手順 3](/run-server/self-hosting/single-server#3-release-입력-생성)で settings digest と release 入力を作り直します。すでに設置済みなら [Compose のアップグレード](/run-server/self-hosting/upgrade-compose)で適用します。設定文書に `profiles` 項目があると import は拒否します。

```json
{
  "connections": {
    "anthropic": {
      "kind": "anthropic",
      "endpoint": "https://api.anthropic.com",
      "auth": { "kind": "api_key", "stored": true },
      "models": ["claude-sonnet-5", "claude-haiku-4-5"]
    }
  }
}
```

こうして import した接続は、値が入るまで `needs_value`（画面では**値が必要**）の状態で、その接続でリリースしたセッションは動きません。**モデル接続**の該当行の ⋯ メニューから**API キーを設定**（Bearer トークンの接続では**Bearer トークンを設定**）を選んでキーを入れます。API では owner のセッションで `POST /v1/installation/settings/connections/{id}/credential` を呼びます。値は 8 バイト以上で、制御文字と前後の空白を含んではいけません。値は `PLATFORM_SECRET_KEY` で暗号化して DB に保存されます。そのあとで設定文書に同じ接続が残っていても、import は DB の行をそのままにします。

<a id="3-설정-문서-가져오기내보내기" />
### 3. 設定文書の import・export

```bash
API_CONTAINER='<api-container-id-from-this-installation>'
docker exec "$API_CONTAINER" bun run apps/control-host/src/api/settings.ts export > settings.json
docker exec -i "$API_CONTAINER" bun run apps/control-host/src/api/settings.ts import --document - --dry-run < settings.json
```

API_CONTAINER はこの設置の status と project label で確認します。Kubernetes では、次の package script に設置バージョンのリポジトリ checkout とホストの Bun・kubectl が必要です。`bun run settings:k8s export` と `bun run settings:k8s import --document - --dry-run` に置き換えます。dry-run の追加項目とエラーを確認してから、同じコマンドから `--dry-run` を外して import します。既存の DB の行をファイルの内容で無条件に上書きするツールではありません。接続の `models` と `model_families` は新しい接続を加えるときに一緒に入り、既存の接続の一覧はコンソールで変えます。資格情報は文書に `"stored": true` とだけ書き、値はコンソールで入れます。

### 4. 課金のないプライベートモデル

<a id="과금-없는-profile-billing-none" />
<a id="과금-없는-연결-billing-none" />
### 課金のない接続（`billing: none`）

セルフホストしたモデル（Ollama、プライベートネットワークの LiteLLM など）にはトークンごとの請求がありません。そのままにすると、価格表にも LiteLLM の単価 snapshot にもない名前には金額が付きませんが、呼び出しは単価不明として記録され、セッションの単価不明トークンの上限（`unknown_price_session_token_limit`）で止まります。snapshot に同じ名前があればその単価で計算され、セッションの費用上限にかかります。このような接続は `billing: none` と宣言します。

```yaml
kind: litellm
endpoint: http://litellm:4000
billing: none
auth:
  kind: bearer
  stored: true
models:
  - qwen3-coder
```

- 省略時は `per_token` で、価格表と LiteLLM の単価 snapshot で計算します。どこにもないモデルは金額なしで単価不明と記します。
- `none` の接続でリリースしたセッションの provider 呼び出しは、応答の model 名によらず費用 0、ledger の `priced_by=unmetered` として記録されます。トークンはそのまま記録されます。セッションの費用が増えないので、費用上限の判定 4 か所（egress 認可、`nextInput`、メッセージ受付、エンジン）にかかりません。
- claim の `remaining_budget_usd` は `null` で、worker は SDK に `maxBudgetUsd` を渡しません。SDK は知らない model を独自の推定単価で計算し、予算で turn を切るためです。縛る予算がないので、`/clear` などで SDK の費用集計がやり直されても worker は drain しません。
- `GET /v1/sessions/{id}/usage` は `cost.kind: "unmetered"` で答え、`amount_usd` は `"0.000000"` です。このセッションには費用上限がかからないので `cost_limit_usd` は `null` で、上限到達の案内（`attention.reason`）にもドルの上限は出ません。`budget_exceeded` はトークン上限に達したときだけ `true` になります。
- 課金の有無はセッション作成時にセッション行（`sessions.unmetered`）へ固定し、価格、claim 予算、usage 表示はこの値を読みます。接続が指す先（endpoint・種類・`billing`・資格情報の出どころ）は変わりません。別の値が必要なら新しい id で接続を加え、エージェントをリリースし直します。
- セッションのトークン上限と時間・同時実行の上限（turn の時間、`EXECUTION_SLOT_LIMIT`、待機メッセージ）はそのままかかります（[Web で決める実行の上限](/run-server/self-hosting/reference/configuration#웹에서-정하는-실행-한도)）。`unmetered` 行のトークンも `sessions.provider_tokens` に加算されます。
- API は endpoint の host がプライベートアドレス（10/8、172.16/12、192.168/16、100.64/10、127/8、`::1`、fc00::/7。link-local アドレスと、`::ffff:10.0.0.1` のように IPv6 の中に書いた IPv4 はプライベートとみなしません）か、公開 DNS にない名前（ドットのない compose のサービス名、`localhost`、`.internal`・`.local`・`.localhost`・`.lan`・`.home.arpa`）のときだけ `none` を受け付けます。egress proxy 側ではその host を `EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST` に置きます。
- プライベートアドレスは必要条件にすぎません。プライベートネットワークの LiteLLM も有料の upstream を代理できます。`none` の宣言が正しいかは運用者の責任です。誤って宣言すると、有料の呼び出しが費用上限なしに出ていきます。セッションのトークン上限を決めておけば、そのときもセッションごとのトークンは縛られます。Datadog の `werft.provider.unmetered_tokens_1h`（直近 1 時間の `unmetered` 行のトークン合計）と provider のコンソールの使用量を一緒に見ます。

有効にする前に[アップグレードのゲート](/run-server/self-hosting/upgrade-compose#실행-전-게이트)を満たす必要があります。

<a id="확인" />
## 確認

この接続でリリースしたエージェントでセッションを作り、turn が completed になることを確認します。ready 200 はモデルのキーや呼び出しの成功を検査しません。設定文書で import した接続にキーを入れたあとは、状態が `needs_value` でなくなったことと新しい呼び出しを確認します。

<a id="자주-막히는-곳" />
## よくある問題

モデルキーがないエラーは、接続画面の場所を確認します。モデル一覧が空の接続ではリリースを作れません。プライベートな endpoint だというだけで billing:none が安全になるわけではありません。有料の upstream を代理するモデルを none と宣言すると、費用上限なしに呼び出されます。

<a id="되돌리기" />
## 元に戻す

接続を無効にすると、その接続のリリースで動くセッションが止まります（`CATALOG_MISMATCH`）。無効にする前に画面の影響数（エージェント・セッション）を確認し、エージェントを別の接続でリリースし直します。コンソールに保存したキーを破棄するときは、provider 側の権限もあわせて整理します。
