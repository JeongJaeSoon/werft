## 무엇을 하게 되나

새 서버를 설치하고 첫 owner, 모델 연결, 에이전트, Slack 앱을 차례로 만든 뒤 Slack 채널에서 에이전트를 멘션해 답을 받는다. 이 페이지는 순서와 단계마다 준비할 것만 적는다. 명령과 화면은 단계마다 링크한 페이지에 있다. 릴리스 번들이나 게시 chart만 있으면 되고 저장소 checkout은 필요 없다.

## 준비물

모델 key와 Slack 토큰은 사람이 직접 받아 콘솔에 붙여 넣는 값이다. 설치를 시작하기 전에 누가 언제 넣을지 정해 둔다.

| 준비할 것 | 쓰는 단계 | 맡는 사람 |
| --- | --- | --- |
| 설치 방식의 준비물. 단일 서버는 `prjquota`로 mount한 XFS 디스크와 영속 AWS S3 bucket, Kubernetes는 PostgreSQL 16과 S3 호환 bucket | 1 | 설치 담당자 |
| 콘솔 주소 `CONSOLE_ORIGIN`. Slack 이벤트 주소를 이 값에서 계산하므로 https 주소여야 한다. 이벤트를 다른 공개 주소로 받으면 2단계에서 그 주소를 따로 저장한다 | 1, 2 | 설치 담당자 |
| Slack이 닿는 공개 https 입구: 공개 DNS 이름, TLS 인증서 | 2 | 네트워크 운영자 |
| owner가 될 사람의 이메일 주소 | 3 | 설치 담당자 |
| 모델 공급자 key. Claude 에이전트는 Anthropic API key, Codex 에이전트는 OpenAI API key | 4 | owner |
| Slack 워크스페이스에서 앱을 만들 수 있는 Slack 계정. 그 계정으로 api.slack.com/apps에서 받은 App Configuration Token의 Refresh Token | 5 | owner 또는 admin |
| 에이전트 앱을 워크스페이스에 설치할 수 있는 Slack 권한. 워크스페이스가 앱 설치에 관리자 승인을 요구하면 승인할 Slack 관리자 | 7 | owner 또는 에이전트 관리자 |
| 에이전트가 답할 Slack 채널 | 7, 9 | 에이전트 관리자 |
| 멘션할 사람의 Werft 계정과 Slack 계정 | 8, 9 | 멘션할 사람 |

## 단계

### 1. 서버 설치

[설치 방식 고르기](/run-server/self-hosting)에서 방식을 고른다. 단일 서버는 [XFS 디스크 준비](/run-server/self-hosting/prepare-xfs)와 [checkpoint bucket 준비](/run-server/self-hosting/prepare-checkpoint-bucket)를 마친 뒤 [단일 서버 설치](/run-server/self-hosting/single-server)를 따른다. Kubernetes는 [Kubernetes 설치](/run-server/self-hosting/kubernetes)를 따르고, 시험 클러스터에 DB와 bucket이 없으면 [chart 시험용 DB와 object store](/run-server/self-hosting/try-chart-dependencies)를 먼저 세운다.

`CONSOLE_ORIGIN`은 이 단계에서 넣는다. 단일 서버는 [2단계 비밀과 설정 문서](/run-server/self-hosting/single-server#2-비밀과-설정-문서), Kubernetes는 [3단계 설치별 values](/run-server/self-hosting/kubernetes#3-설치별-values)다. 이 값이 없어도 설치와 로그인은 되지만 콘솔에서 Slack 앱을 만들 수 없다.

설치 페이지의 확인 절대로 `/readyz`가 `200`을 돌려주면 다음 단계로 간다.

### 2. 콘솔 입구와 Slack 공개 입구

[사용자 접속 경로 구성](/run-server/self-hosting/access)을 따른다. 콘솔은 SSH tunnel이나 VPN·IP allowlist 안의 입구로만 연다. Slack이 부르는 두 경로는 [공개 입구: Slack 경로만 열기](/run-server/self-hosting/access#공개-입구-slack-경로만-열기)대로 공개 https 입구에 따로 연다. api 포트를 통째로 공개하면 worker용 `/internal`까지 열리므로 그렇게 하지 않는다.

공개 입구의 DNS 이름이 `CONSOLE_ORIGIN`과 다르면, 3단계에서 owner를 만든 뒤 같은 절의 안내대로 owner가 이벤트 입구 주소를 저장한다. 5단계보다 먼저 한다.

### 3. 첫 owner

[첫 owner 만들기](/run-server/self-hosting/users-and-keys#1-첫-owner-만들기)를 따른다. 운영자가 설치 쪽 명령으로 일회용 설정 링크를 파일로 받고, owner가 될 사람이 그 링크를 열어 owner와 workspace를 만든다. 콘솔을 열 브라우저가 없는 호스트에서는 [브라우저 없이 만들기](/run-server/self-hosting/users-and-keys#브라우저-없이-만들기)를 따른다.

owner로 콘솔에 로그인되면 다음 단계로 간다.

### 4. 모델 연결

owner가 [콘솔 연결과 모델 목록](/run-server/self-hosting/model-connections#1-콘솔-연결과-모델-목록)대로 **설정 > 에이전트 연결 > 모델 연결**에서 연결을 더하고 key를 붙여 넣은 뒤, 에이전트가 쓸 모델을 저장한다. 모델을 하나 이상 저장해야 6단계에서 그 연결을 고를 수 있다.

### 5. Slack 앱 생성 토큰

콘솔이 에이전트의 Slack 앱을 만들려면 워크스페이스에 App Configuration Token이 있어야 한다. owner나 admin이 **설정 > 워크스페이스 > 연동 > Slack**의 **Slack 앱 생성**에서 **토큰 등록**을 누르고 화면의 순서를 따른다.

1. api.slack.com/apps를 열고, App Configuration Token 목록에서 이 Slack 워크스페이스의 **Generate Token**을 누른다.
2. 만들어진 두 값 가운데 `xoxe-1-`로 시작하는 Refresh Token을 붙여 넣고 **등록**을 누른다. Access Token이 아니다.

등록하면 서버가 Slack에서 바로 새 토큰으로 바꾸므로 붙여 넣은 값은 다시 쓸 수 없다. 토큰을 만든 Slack 사용자는 이 콘솔이 만드는 앱의 협업자가 된다. **토큰 확인됨**이 보이면 다음 단계로 간다.

### 6. 에이전트 만들기

새 설치에는 팀이 없고, 에이전트에는 담당 팀이 있어야 한다. owner가 먼저 **구성원** > **팀**에서 **팀 만들기**로 팀을 하나 만든다. 팀이 없을 때 새 에이전트 화면에 나오는 **팀으로** 버튼도 같은 화면을 연다. 그다음 **에이전트**에서 **새 에이전트**를 누르고 이름과 담당 팀을 정한다. **하는 일** 단계에서 4단계의 연결과 모델을 고르고 **저장하고 미리 써 보기**를 누르면 에이전트와 첫 release가 저장된다. release는 아직 켜지지 않는다. **미리 써 보기** 단계에서 메시지를 **보내기**로 보내면 4단계의 key로 모델이 답하는지 미리 볼 수 있다. **게시**를 누르고 확인 창에서 다시 **게시**를 누르면 release가 켜지고 **채널 연결** 단계가 열린다. 그러면 다음 단계로 간다. 에이전트와 release의 개념은 [에이전트 만들기](/agents/create)에 있다.

### 7. Slack 앱 설치와 홈 채널

**채널 연결** 단계나 에이전트 상세의 **Slack** 탭에서 [콘솔에서 Slack 연결](/integrations/slack-console)의 1~3번을 따른다. **Slack 앱 만들고 설치**를 누르고, Slack 동의 화면에서 앱을 설치하고, 돌아온 화면의 **홈 채널 고르기**에서 에이전트가 답할 채널을 고른다. 공개 채널에는 서버가 봇을 참여시킨다. 비공개 채널은 Slack에서 `/invite @<에이전트 slug>`로 봇을 먼저 초대한다.

**Slack** 카드의 배지가 **연결됨**이고 **Slack 앱에 넣을 주소**의 **이벤트 요청 URL**이 확인됨이면 다음 단계로 간다.

### 8. Slack 계정 연결

에이전트는 Werft 계정에 연결된 Slack 사용자의 멘션에 답한다. 연결하지 않은 사람이 멘션하면 답 대신 계정을 연결하라는 안내와 링크가 온다. 멘션할 사람이 콘솔에 로그인해 사용자 메뉴의 **연동 계정**에서 **Slack 계정 연결**을 누르고 Slack에서 동의한다. 첫 확인은 owner가 하면 된다. 다른 사람은 먼저 [구성원](/members)으로 초대하고 에이전트의 담당 팀에 넣는다. 연결 조건과 오류는 [Slack](/integrations/slack)의 "Slack 계정 연결"에 있다.

**연동 계정**의 Slack 행이 **연결됨**이면 다음 단계로 간다.

### 9. Slack에서 멘션

홈 채널에 `@<에이전트 slug>`를 넣어 글을 쓴다. 에이전트는 그 글의 스레드에 답한다. 같은 스레드에 쓴 답글은 멘션 없이도 같은 세션으로 이어진다. 다른 봇이 쓴 멘션에는 그 봇을 [Slack](/integrations/slack)의 "다른 봇의 멘션"대로 답할 봇 목록에 넣어야 답한다.

## 확인

멘션한 글의 스레드에 에이전트의 답이 달리면 첫 설치가 끝난 것이다. 웹 콘솔의 세션 화면에는 그 대화가 세션으로 보이고 **Slack에서 보기** 링크가 붙는다([Slack](/integrations/slack)의 "원래 Slack 메시지 링크"). 이 답은 4단계의 key로 모델 호출이 된다는 증거이기도 하다. `/readyz`의 `200`은 모델 호출을 검사하지 않는다.

## 자주 막히는 곳

| 증상 | 볼 곳 |
| --- | --- |
| **Slack 앱 만들고 설치**가 꺼져 있다 | 버튼 아래의 이유를 본다. 토큰이 없거나 다시 등록해야 하면 5단계로 돌아간다. 콘솔 주소를 알 수 없다는 이유면 1단계의 `CONSOLE_ORIGIN`을 넣는다 |
| 이벤트 요청 URL이 확인 대기나 등록 실패에 머문다 | Slack이 공개 입구에 닿지 않는다. 2단계의 공개 입구를 고친 뒤 **Slack** 탭의 **다시 확인**을 누른다 |
| 멘션해도 답이 없다 | 그 채널이 연결돼 있고 **이 채널에서 사용**이 켜져 있는지 본다. 비공개 채널은 봇을 초대했는지 본다. 에이전트 목록의 **Slack 조치 필요** 링크가 남은 일을 알려 준다 |
| 답 대신 계정을 연결하라는 안내가 온다 | 멘션한 사람의 Slack 계정이 연결되지 않았다. 8단계를 따른다 |
| 모델 연결에 쓸 수 있는 키가 없다는 오류 | 4단계의 연결에 key를 넣는다 |

## 되돌리기

Slack 쪽은 에이전트 **Slack** 탭의 **위험 구역**에서 연결을 해제하거나 앱을 삭제한다([콘솔에서 Slack 연결](/integrations/slack-console)). 서버는 단일 서버면 [Compose 중지·재시작·제거](/run-server/self-hosting/stop-compose), Kubernetes면 [Kubernetes 중지·제거](/run-server/self-hosting/remove-kubernetes)를 따른다.
