## Contract

`WERFT_API_KEY` and `WERFT_BASE_URL` configure SDK callers, not the server. See [SDK client configuration](/getting-started/client).

This reference covers formats, requirements, and when settings apply. Read [Compose upgrades](/run-server/self-hosting/upgrade-compose) and [Kubernetes upgrades](/run-server/self-hosting/upgrade-kubernetes) first for activation and rollback gates.

<a id="설치-상한" />
## Installation limits

API and scheduler refuse startup if any of the six required values below (all except SESSION_TOKEN_LIMIT) is missing, or any value has an invalid format. They log all problems on one line using the same parser. Missing SESSION_TOKEN_LIMIT means 0 (unlimited). Apart from that 0, code has no defaults; Compose x-installation-limits provides local defaults. Running API readyz repeats the same validation as its config check.

| Variable | Meaning | When exceeded |
|---|---|---|
| `EXECUTION_SLOT_LIMIT` | Concurrent workers holding slots. 0 accepts input but launches nothing | Input remains accepted as queued |
| `QUEUED_INPUT_LIMIT_PER_SESSION` | Queued turns allowed per session | `429 RATE_LIMITED`, `retryable:true`, `Retry-After: 5` |
| `STORAGE_LIMIT_BYTES` | Installation-wide retained input-message UTF-8 bytes, excluding events/checkpoint objects/worker disk (workspace quotas cover disk) | `413 STORAGE_LIMIT_EXCEEDED`, `retryable:false` |
| `MAX_TURN_SECONDS` | Turn wall-clock limit including approval waits, passed as `WORKER_MAX_TURN_SEC` | `failed(turn_timeout)`, or `outcome_unknown(turn_timeout)` if engine does not respond |
| `SESSION_COST_LIMIT_USD` | Estimated cumulative session cost: proxy-metered Messages usage converted through platform prices | No new turn dispatch; session attention.code=BUDGET_EXCEEDED; worker releases slot. Input still accepted as queued |
| `SESSION_TOKEN_LIMIT` | Cumulative provider tokens from the same calls, independent of prices. 0 is unlimited (default) | Same as SESSION_COST_LIMIT_USD. Shared budgetExceeded returns BUDGET_EXCEEDED for whichever limit is reached first; attention.reason names only reached limits |
| `PROVIDER_MAX_RETRIES` | Retries for failed Messages requests, passed through WORKER_PROVIDER_MAX_RETRIES to SDK CLAUDE_CODE_MAX_RETRIES. 0 ends the turn on first failure | `failed(api_error)`; turn result retains api_error_status/provider_error/last_retry_status |

<a id="api-설정" />
## API settings

At startup, API reads these through one parser. Unset values use defaults; invalid configured values (including empty strings) never silently fall back. API/scheduler/reconciler/worker numeric settings and installation limits share this rule. Missing required settings return `X is required`; invalid values describe the expected range, such as `X must be a positive integer`, without echoing the value, which could be a misplaced secret. All problems appear in one `Refusing to start: API settings are invalid` log line; startup stops. Running readyz repeats config validation.

| Variable | Default | Allowed range |
|---|---|---|
| `HEARTBEAT_TTL_SEC` | 30 | Greater than 20, at most 86400. Workers relinquish leases 10 seconds early (WORKER_LEASE_SAFETY_MARGIN_SEC) and heartbeat every 5 seconds (WORKER_HEARTBEAT_INTERVAL_SEC; older workers 10). A TTL at or below margin + 10 seconds loses old attempts around their first heartbeat. Launchers do not pass these two worker settings, so validation uses defaults |
| `PENDING_REQUEST_TTL_SEC` | 1800 | Integer 1–604800. Lifetime of approval/question requests. Workers wait this long after registration. QUESTION_TIMEOUT_SEC applies only before gateway registration confirmation. MAX_TURN_SECONDS includes waits and still bounds them |
| `SSE_MAX_STREAMS` · `SSE_MAX_STREAMS_PER_OWNER` · `SSE_REPLAY_MAX_BYTES` | 256 · 8 · 1 MiB | Positive integers |
| `LOG_LEVEL` | `info` | debug/info/warn/error, case-insensitive; empty means info. Scheduler/reconciler loops and egress-proxy reject invalid values by the same rule. Workers inherit scheduler's value |
| `WEB_DIST_DIR` | Unset (no console); control-host image: `/app/apps/web/dist` | Absolute path containing index.html, the apps/web build output |

Every /v1 response logs `api.request.completed`: Hono route_template without actual ids, method, status, duration_ms including auth/routing, operation=api_request, outcome, reason_code, and request_id in log context. Bodies/credentials/provider keys are excluded. Terminate also logs `Terminate control transaction completed` under the same request_id, with millisecond pool checkout, binding/launch/session locks, individual SQL, commit/rollback, and total control-transaction timing. Join the logs by request_id to diagnose acceptance latency.

Immediate terminate of an already absent execution, or scheduler/reconciler confirmation of absence, emits control.result with operation=terminate, receipt control_id, outcome, reason_code, and effect_ms from durable acceptance to confirmation (equal to duration_ms). Overdue receipts first emit outcome=unknown/reason_code=deadline_exceeded; later confirmed absence upgrades the receipt and adds outcome=succeeded/reason_code=execution_gone.

WEB_DIST_DIR enables same-origin console serving. GET/HEAD outside /v1 and /internal serve files or index.html SPA fallback, allowing /login and /bootstrap refreshes. No fallback applies under /v1 or /internal; authenticated /v1/nope returns JSON 404 NOT_FOUND. Hashed /assets/ files cache immutable; missing assets return 404, not a page. index.html uses no-cache and CSP `script-src 'self'`, prohibiting inline scripts. control-host's web build stage builds apps/web and retains only dist; no separate web image exists. For local web-only work, `bun run --cwd apps/web dev` uses Vite and proxies /v1 to VITE_API_TARGET (default `http://127.0.0.1:3000`).

AUTH_MODE=none cannot coexist with EGRESS_AUTHORIZER_PORT. An enabled authorizer means workers reach API through proxy; none would let worker code impersonate arbitrary owners via X-Owner-Id, so startup refuses. Readiness validates AUTH_MODE itself (none|api-key).

Workers also cross-check startup settings. Missing WORKER_PROVIDER_MAX_RETRIES fails: this installation limit has no code default and scheduler always passes it. WORKER_NEXT_INPUT_WAIT_SEC must be below WORKER_REQUEST_TIMEOUT_SEC or every long poll times out. Scheduler/reconciler treat empty DATABASE_URL as unset and fall back to QUEUE_DATABASE_URL.

API/slack read current/previous runtime combinations through WORKER_IMAGE_RUNTIME/WORKER_IMAGE_PREVIOUS_RUNTIME. Copy runtime from images.yml worker digest JSON rather than typing it (`{"engine":…,"sdkVersion":…,"cliVersion":…,"profileDigestScheme":…}`). The engine is `claude` or `codex`; other names fail rendering with `images.worker.runtime.engine must be one of: claude, codex`. Custom images lack that JSON; extract with the same command:

```bash
docker run --rm -i --network none --entrypoint bun <worker-image> \
  run apps/worker/src/image-runtime.ts <<<'{}' | jq -c 'del(.profiles)'
```

**One worker image holds one engine.** `apps/worker/Dockerfile` picks it with the build argument `WORKER_RUNTIME`. Empty builds the Claude image; `--build-arg WORKER_RUNTIME=codex_app_server` builds the Codex image (the build log prints `codex-cli 0.167.0`, and any other version fails the build). CI builds the Codex image as its own image, `werft-worker-codex`. A deployment that runs Codex points `WORKER_IMAGE` (the chart's `images.worker`) at that image and sets the `runtime` read with the command above (`engine` is `codex`). The local stack builds the same image with the `infra/compose.codex-worker.yml` overlay. A deployment whose Codex sessions call the real OpenAI Responses API also adds `api.openai.com:443` to the proxy's `EGRESS_CREDENTIAL_ALLOWLIST`. The Codex engine has no budget of its own. The session cost and token limits (`SESSION_COST_LIMIT_USD`, `SESSION_TOKEN_LIMIT`) are enforced by the worker gateway on every provider call from the stored usage, and a session past a limit gets `403 BUDGET_EXCEEDED` on its next call. Limit of this: usage reaches the gateway through the proxy's report. A report lost after its retries (1s, 5s, 15s) leaves the stored cost low, and that session's later provider calls are then stopped only by the proxy's in-process gate (one process, lost on restart). The limit is therefore a soft one that relies on the stored usage. After a lost report, with several proxies or a restart, the overshoot has no bound. Even with every report delivered, one long response, parallel calls, and a call sent while a report is still in flight can pass the limit (the Claude engine's budget is also checked only after a call completes). Closing this with durable usage records is follow-up work.

**Switching engines.** One deployment cannot pick between two engines' images at once: new sessions always start on the current image, and the previous image only resumes checkpoints. Choosing the engine at install time is the simplest path. To replace the `WORKER_IMAGE` of a running deployment with another engine's image, follow the upgrade check (`upgrade-check`) as it is: the new configuration's `WORKER_IMAGE_PREVIOUS` must be the image deployed now, and every session the check reports as unresumable (not only a different checkpoint engine, but also a mismatched SDK or CLI version or digest scheme, or an unrecorded runtime) must be approved in `upgrade.approvedSessions` as exactly the list the check prints. Checkpoints do not move between engines, so the previous (old-engine) image can only be emptied once the sessions resuming on it have ended.

With neither runtime, no runtime reading or pin preservation applies. Previous-only or unreadable values reject startup. When configured, releases made with the previous image and their sessions keep running. A release pins the runtime version its image shipped when it was made, so a release whose version neither the current nor the previous image ships takes no new session; release that agent again.

Set the following only to send GitHub Packages bot tokens ([decision](https://github.com/JeongJaeSoon/werft/blob/main/docs/contributing/decisions/github-packages-bot-token.md)) to another host, such as GHES/test registries. URLs must be http(s) without userinfo/query/fragment, or startup fails. Hosts must also be in proxy EGRESS_CREDENTIAL_ALLOWLIST, or EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST for private addresses.

| Variable | Default | Meaning |
|---|---|---|
| `GITHUB_PACKAGES_API_URL` | `https://api.github.com` | Queries token scopes (GET /user) |
| `GITHUB_PACKAGES_NPM_URL` | `https://npm.pkg.github.com` | github-npm upstream |
| `GITHUB_PACKAGES_RUBYGEMS_URL` | `https://rubygems.pkg.github.com` | github-rubygems upstream |

## Scheduler, worker container, and egress settings

Scheduler reads these to create workers. Unset values use defaults; invalid formats reject startup. User, HOME/workspace paths, tmpfs sizes, credential port, and stop timeout enter werft.isolation ([isolation](/run-server/self-hosting/explanation/isolation)); changing them replaces running workers. CPU/memory/PID limits apply next launch.

WORKER_MEMORY_MB is chosen with MAX_TRANSCRIPT_BYTES; see [capacity](/run-server/self-hosting/capacity) for measurements, node counts, and changes.

Scheduler receives current WORKER_IMAGE/WORKER_IMAGE_RUNTIME and previous WORKER_IMAGE_PREVIOUS/WORKER_IMAGE_PREVIOUS_RUNTIME, using API-equivalent runtimes. Previous image/runtime must be set together; one alone fails. Without current runtime every launch uses current image. Otherwise, match each checkpoint engine/SDK/CLI/profile digest scheme to current/previous, preferring current when both match. New sessions, checkpoint-free sessions, and old unrecorded checkpoints use current. No match stops before launch as recovery_required (incompatible_checkpoint), with checkpoint_restore_failed detected_at: "launch". retry_restore is available.

Workers report actual image runtime at claim. Mismatch causes API LAUNCH_FAILED with reason_code worker_image_mismatch and records refusal for that image/configuration. Further launches for it wait; scheduler logs images_refused as error and exits 1. Correcting image configuration (changed values) restores launches next pass. Sessions themselves do not become failed.

Deploy API first, then scheduler WORKER_IMAGE: new workers send claim image_runtime, rejected by old APIs.

| Variable | Default | Meaning |
|---|---|---|
| `WORKER_CPUS` | 1 | CPU share/worker, at least 0.01 |
| `WORKER_MEMORY_MB` | 4608 | The per-worker memory limit (MiB) keeps the engine's peak below half the limit when resuming an uncompacted 512MiB transcript. The development `.env.example` setting `WORKER_MEMORY_MB=2048` does not meet this criterion. For large-transcript restoration tests, remove that `WORKER_MEMORY_MB` line to use the default, or set it to 4608 MiB or more |
| `WORKER_PIDS_LIMIT` | 512 | PID limit; not forwarded by Compose |
| `EXECUTION_DOCKER_USER` | `1000:1000` | Numeric uid[:gid], rejecting uid/gid 0. Must match image /workspace ownership |
| `EXECUTION_DOCKER_HOME_DIR` | `/home/worker` | Absolute tmpfs HOME |
| `EXECUTION_DOCKER_WORKSPACE_DIR` | `/workspace` | Absolute session-volume path, distinct from HOME, without spaces/backslashes; passed as WORKER_WORKSPACE_DIR |
| `EXECUTION_DOCKER_TMPFS_SIZE_MB` | 256 | MiB for each HOME and /tmp tmpfs |
| `EXECUTION_DOCKER_STOP_TIMEOUT_SEC` | 120 | SIGTERM-to-SIGKILL grace, at least 30. Passed as WORKER_STOP_GRACE_SEC; worker fits drain inside it |
| `EXECUTION_DOCKER_REQUEST_TIMEOUT_SEC` | 30 | Per Engine API request deadline |
| `EXECUTION_DOCKER_COMMAND` | Unset | Space-split command replacing image entrypoint, for tests |
| `DOCKER_HOST` | `unix:///var/run/docker.sock` | Daemon address |
| `DOCKER_API_VERSION` | `v1.44` | Engine API request version |
| `EXECUTION_EGRESS_CREDENTIAL_PORT` | 3129 | Must equal proxy EGRESS_CREDENTIAL_PORT and differ from EXECUTION_EGRESS_PROXY_URL port |

EXECUTION_DOCKER_NETWORK/EXECUTION_DOCKER_NETWORK_ALLOWLIST are no longer read; configured values reject startup.

Proxy and API authorizer use these settings. Lists **replace**, rather than extend, defaults: restate required providers/registries when adding GitHub/bucket hosts. Public credential lists must match in proxy/API. Private lists enforce proxy rejection but only console warnings in API. Matching private lists is recommended, not required; core/local-model role defaults also differ.

| Variable | Default | Helm values | Meaning/startup constraints |
| --- | --- | --- | --- |

| `EGRESS_CREDENTIAL_ALLOWLIST` | Compose core/local: `api.anthropic.com:443,api.openai.com:443,registry.npmjs.org:443,rubygems.org:443,proxy.golang.org:443,sum.golang.org:443`; test-ops: required, no default; chart: same as core/local | `config.egress.credentialAllowlist` | Credential public destinations for API/proxy. Missing test-ops values fail Compose. Replaces defaults: restate every required entry when adding GitHub/checkpoint hosts |
| `EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST` | Chart/Compose core proxy: empty; Compose core API/local proxy: `fake-git:3000,fake-messages:4010,fake-mcp:4020,localstack:4566` | `config.egress.credentialPrivateAllowlist` | Private proxy enforcement/API warnings. test-ops LocalStack requires localstack:4566; example uses only that. local-model overlay: `fake-git:3000,localstack:4566,ollama.internal:11434,litellm:4000`. Compose's three ports/two internal URLs come from x-egress-ports at the top of infra/compose.core.yml. Proxy EGRESS_PROXY_PORT/EGRESS_CREDENTIAL_PORT/EGRESS_AUTHORIZER_URL, API EGRESS_AUTHORIZER_PORT, and scheduler EXECUTION_EGRESS_PROXY_URL/EXECUTION_EGRESS_CREDENTIAL_PORT all use it. Change listener/URL pairs together. A test compares both URL ports with all three listeners in `docker compose config`.

API memory is determined by checkpoint bundle validation: at most two validations concurrently, each running git fetch and index-pack together under individual CHECKPOINT_GIT_MEMORY_MB address-space limits. Change both settings together; raising only the limit leaves OOM victim selection to the kernel. See the api service comment in infra/compose.core.yml.

|---|---|---|
| `API_MEMORY_MB` | 7168 | Compose api mem_limit, MiB |
| `CHECKPOINT_GIT_MEMORY_MB` | 1536 | Per-git-process address-space MiB, minimum 512 |

Workers also read the following env settings, but scheduler does not forward them, so production uses code defaults: WORKER_ANSWER_POLL_SEC (1), WORKER_ATTACH_FETCH_TIMEOUT_SEC (300, fetch one repository attached mid-session), WORKER_ATTACH_FETCH_MAX_MB (2048, fetched scratch mirror size), WORKER_CLAIM_TIMEOUT_SEC (60), WORKER_DRAIN_TIMEOUT_SEC (100, reduced to fit stop grace), WORKER_HEARTBEAT_INTERVAL_SEC (5), WORKER_IDLE_TIMEOUT_SEC (1800), WORKER_LEASE_SAFETY_MARGIN_SEC (10), WORKER_NEXT_INPUT_RETRY_SEC (60), WORKER_NEXT_INPUT_WAIT_SEC (20), WORKER_REQUEST_TIMEOUT_SEC (30), WORKER_STARTUP_TIMEOUT_SEC (3600), QUESTION_TIMEOUT_SEC (1800), WORKER_CLAUDE_CONFIG_DIR ($HOME/.claude).

## Kubernetes env and values

EXECUTION_BACKEND selects local_docker (default, also when empty) or kubernetes; other values reject startup with an error naming the value. Kubernetes ignores Docker settings (DOCKER_HOST, EXECUTION_DOCKER_*, EXECUTION_WORKSPACE_QUOTA) and socket, and skips Docker egress-isolation/quota preflights. Chart NetworkPolicy provides isolation; the workspace requests PVC size, while actual enforcement depends on storage. Fixed stop/request timeouts are 120s + 30s, requiring SCHEDULER_PASS_TIMEOUT_SEC >150. migrate-workspace is local_docker-only.

On readOnlyRootFilesystem Pods, status files need writable directories. Default /tmp/scheduler-status.json and /tmp/reconciler-status.json work with /tmp emptyDir. Override paths with SCHEDULER_STATUS_FILE/RECONCILER_STATUS_FILE. Loops write adjacent `<status file>.<pid>.tmp` then rename; scheduler also stores .quota-verified nearby. The whole directory, not just the file, must be writable.

Shared env matches Docker: WORKER_IMAGE, WORKER_GATEWAY_URL, EXECUTION_EGRESS_PROXY_URL, EXECUTION_EGRESS_CREDENTIAL_PORT, EXECUTION_INSTALLATION_ID, EXECUTION_WORKSPACE_QUOTA_MB, EXECUTION_WORKSPACE_GC_MIN_AGE_SEC, S3_BUCKET, AWS_REGION. Kubernetes adds constraints:

- WORKER_IMAGE must be `repository@sha256:<digest>`.
- EXECUTION_INSTALLATION_ID must be a lowercase DNS label, at most 32 characters.

Kubernetes-only settings:

`EXECUTION_WORKSPACE_ENFORCED_BY_STORAGE` defaults to `false` when unset and accepts only exact `true`/`false`. Empty values, whitespace, uppercase, `1`/`0`, and `on`/`off` reject startup without exposing the original value. Helm generates it from `worker.workspace.enforcedByStorage` (default `false`): an operator declaration that storage hard-enforces requested bytes for every workspace PVC in this installation, including existing PVCs. With an empty StorageClass, the cluster default applies and operators must verify enforcement for each PVC. Werft does not verify it. Only the declaration path passing the heuristics of a dedicated writable mount (not `/`, `rw` present, `ro` absent), filesystem size 0.95–1.05 times the request, and PVC capacity at least the request yields bytes `hard`/inodes `unknown`. See [Storage and limits](/run-server/self-hosting/reference/storage). Changing the declaration leaves PVCs, the isolation stamp, and existing Pod env unchanged; only new Pods receive the new value.

| Variable | Meaning |
| --- | --- |
| `EXECUTION_K8S_NAMESPACE` | Namespace for worker Pods/Secrets/PVCs; defaults to scheduler namespace, required outside cluster |
| `EXECUTION_K8S_WORKER_SERVICE_ACCOUNT` | Worker ServiceAccount; token is always unmounted |
| `EXECUTION_K8S_STORAGE_CLASS` | Workspace StorageClass; empty uses cluster default |
| `EXECUTION_K8S_IMAGE_PULL_SECRETS` | Optional comma-separated Secret names |
| `EXECUTION_K8S_WORKER_NODE_SELECTOR` | Optional JSON object |
| `EXECUTION_K8S_WORKER_TOLERATIONS` | Optional JSON array |
| `EXECUTION_K8S_WORKER_EPHEMERAL_STORAGE_MB` | Ephemeral-storage requests/limits MiB, default 1024; exceeding it causes kubelet eviction |

Scheduler logs failed-worker termination reasons and last 8 KiB under `Execution resource failed; log tail kept`. See storage/retention in the repository's Kubernetes execution adapter README.

## Probes

## Usage and cost metering

- Credential routes meter session cost. Proxy reads usage from 2xx /v1/messages responses, JSON or SSE, and reports POST /usage to authorizer when responses finish/disconnect. count_tokens/error responses do not count.
  - Incomplete usage is estimated conservatively. Streams ending before message_stop count each delivered content character as one output token and each delivered web-search result block as one search. Unreadable JSON (truncated, over 8 MiB, or invalid JSON) uses request estimation: 1 request byte/input token and full max_tokens/output. Proxy logs Provider usage estimated; ledger estimated=true.
  - API converts through prices to USD, rounds up to micro-dollars, writes one provider_usage row/exchange and adds session cost in the same transaction, keeping ledger/session totals aligned.
  - Engine calls and tool calls made directly with engine tokens are metered equally.
  - Proxy assigns exchange ids. Failed authorizer reports retry after 1, 5, and 15 seconds; ids count once. Final failure logs Provider usage went unreported and leaves that exchange uncounted.
- SDK turn-end total_cost_usd increments appear only in turn result cost_usd, not session cost. Engine maxBudgetUsd still uses SDK values. Pre-proxy-metering sessions retain costs previously accumulated from SDK values.
- Platform code owns prices by model: input/output/cache write (5-minute 1.25×, 1-hour 2×)/cache read. New models/prices require release updates.
  - Fast prices currently cover Opus 5.5 ($8/$40) and Opus 5/Opus 4.8 ($10/$50). Cache multipliers apply to fast prices. speed uses response usage.speed, then request speed, then standard.
  - Unknown models, fast responses without fast prices, or unknown speed values use per-item highest rates across both tables. Authorizer warns Provider usage priced at the fallback rate; ledger priced_by=fallback. When a model the Claude table does not name is priced at the highest rates, it may be an OpenAI call: a model neither table names, or an OpenAI model past 272K input tokens whose table has no long-context rates. Then, when the speed is not `standard`, the highest rates are multiplied by OpenAI's fast multiplier (2x). At any speed a cache write is counted at 1.25x the input rate, a long-lived one at 2.5x (OpenAI's 12-hour write). A model the Claude table names does not get these multipliers.
  - Response usage.server_tool_use web searches add $0.01 each ($10/1,000). Web fetch has no charge beyond tokens. Code execution is excluded: free with web search/fetch, otherwise billed by container time with organizational free allowances, not invocation count. All three counts and speed are recorded in provider_usage.
  - Models from 4.6 onward apply 1.1× to every token price (fast/cache included) for inference_geo: "us", excluding web-search fees. Geo follows response usage.inference_geo, then request inference_geo, then unknown (workspace may default to us). Non-global/us values use highest prices ×1.1, priced_by=fallback. Ledger records inference_geo. Old APIs reject this new field with 400, causing unreported exchanges. Update API including migration before proxy ([Compose order](/run-server/self-hosting/upgrade-compose#2-api--proxy--worker-순서), [Kubernetes order](/run-server/self-hosting/upgrade-kubernetes#1-대상-chart와-제어-영역-우선-교체)). New API accepts old reports without it.
  - Pre-4.6 models (Opus 4.5/4, Sonnet 4.5/4, Haiku 4.5) do not support inference_geo and use standard prices regardless of geo. Their window is 200K without published long-context rates; input+cache write+cache read over 200K uses highest prices, priced_by=fallback. Models 4.6 onward use standard prices for the full 1M.
  - Batch is irrelevant: credential routes do not expose /v1/messages/batches.
- Token limits sum input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens from each provider_usage row into sessions.provider_tokens through an INSERT trigger in the same transaction. This includes calls from pre-0127 APIs during rollout/rollback. Cache reads count as model-processed tokens; estimates count as estimated. The migration backfills provider_usage totals, but cannot recover tokens from older SDK-cost-only sessions. Totals saturate at 2^53-1 (Number.MAX_SAFE_INTEGER, migration 0129). Numeric trigger arithmetic prevents oversized tokens from rolling back usage/cost writes.
  - SDK has no token-budget option; in-turn enforcement relies on egress rejection/reauthorization below. Calls opened after reaching limits are rejected and turns finish failed(budget_exceeded); later turns are blocked with BUDGET_EXCEEDED. Proxy uses Messages error format with message starting BUDGET_EXCEEDED:, but does not determine reason from text. Engine reports the 403 as api_error; exchanges cut by reauthorization also remain api_error if retries are exhausted (PROVIDER_MAX_RETRIES=0). Finalize converts api_error to budget_exceeded and receipt BUDGET_EXCEEDED if the session is already over budget, clearing provider_error diagnostics. A 403 below limits remains api_error.
- Cost/token limits are judged after calls finish. Concurrent open calls may all pass authorization; active turns can exceed limits.
- Authorizer rejects provider egress tokens at or above cumulative cost/token limits with 403 BUDGET_EXCEEDED. New exchanges fail immediately; open exchanges disconnect at the next reauthorization (every 30 seconds). Repository/object-store routes remain available.
