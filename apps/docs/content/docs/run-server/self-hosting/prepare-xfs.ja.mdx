## 作業内容

Docker data-root を XFS prjquota 上に配置し、workspace の byte・inode 上限を強制します。既存のディスク、イメージ、Docker データは保持します。リリースバンドルの `scripts/prepare-xfs.sh` が事前検査から確認までを一度に行い、ある段階が失敗するとそれより前の段階を元に戻します。

<a id="준비물" />
## 準備

運用に使う Linux サーバーで実行します（先に別の試験サーバーで検証してください）。root 権限、systemd で動いている Docker Engine、xfsprogs・rsync、原本全体を保管できる空間、メンテナンス時間が必要です。スクリプトは[リリースバンドル](/run-server/self-hosting/single-server#릴리스-번들로-받기)を展開したディレクトリの `scripts/prepare-xfs.sh` です。リポジトリの checkout にも同じパスにあります。Docker Desktop はこの設置経路に対応していません。

xfsprogs と rsync はディストリビューションのパッケージ管理ツールでインストールします。apt を使うディストリビューションでは次のとおりです。

```bash
sudo apt-get install -y xfsprogs rsync
```

<a id="단계" />
## 手順

<a id="1-현재-상태-확인" />
### 1. 現在の状態を確認

```bash
findmnt -no FSTYPE,OPTIONS -T "$(docker info -f '{{.DockerRootDir}}')"
P="quota-probe-$(date +%s)"; docker volume create --driver local --opt size=64m "$P" && docker volume rm "$P"
```

XFS と prjquota が既に適用され、probe が成功すれば、このページの残りは飛ばします。この状態ではスクリプトも何も変更せずに終了します。quota probe が失敗したら、原因を解消するまで deploy しません。

<a id="2-dry-run으로-사전-검사" />
### 2. dry-run で事前検査

バンドルのディレクトリで実行します。

```bash
sudo bash scripts/prepare-xfs.sh --dry-run
```

dry-run は事前検査だけを行い、実行する段階を表示します。ホストは変更しません。事前検査は次を確認します。

- root で実行しており、`mkfs.xfs`、`rsync`、`findmnt` などの必要なコマンドがあること。
- Docker が systemd で動き、live-restore が無効で、data-root が `/var/lib/docker` であること。live-restore が有効だと Docker を止めてもコンテナが書き込みを続けるため、拒否します。そのパスが symlink や mount ポイントではないこと。
- `/var/lib/docker.xfs.img`、`/var/lib/docker.old`、`/etc/fstab.before-prepare-xfs` がなく、`/etc/fstab` に `/var/lib/docker` の項目がないこと。現在の `/etc/fstab` で `findmnt --verify` がエラーを見つけないこと。
- `/var/lib` にイメージサイズ分の空きがあること。
- カーネルが XFS に対応し、一時的な 512M イメージを loop と prjquota で試験 mount できること。試験イメージは検査の後に削除します。

検査が一つでも失敗すると、理由と `nothing was changed` を表示し、終了コード 1 で終わります。loop デバイスや XFS 対応がないサーバー（コンテナ型サーバーなど）は、Docker を止める前にここで止まります。

<a id="3-디스크-준비-실행" />
### 3. ディスクの準備を実行

```bash
sudo bash scripts/prepare-xfs.sh
```

スクリプトは同じ事前検査をもう一度行い、次を順に実行します。Docker の停止、`/var/lib/docker` から `/var/lib/docker.old` への移動、60G の sparse イメージ `/var/lib/docker.xfs.img` の作成と `mkfs.xfs`、`loop,prjquota` での mount、原本のコピー（`rsync -aHAX`）、`/etc/fstab` を `/etc/fstab.before-prepare-xfs` にバックアップしてから次の項目の追加と `findmnt --verify`、Docker の起動、data-root・mount・quota probe の確認。

```text
/var/lib/docker.xfs.img /var/lib/docker xfs loop,prjquota 0 0
```

スクリプトがこの項目を `/etc/fstab` に自分で追記するため、エディタで編集する必要はありません。この段階の `findmnt --verify` は終了コード 0 のまま警告を 2 つ出すことがあり、どちらも正常です。`non-bind mount source /var/lib/docker.xfs.img is a directory or regular file` は、loop mount の source が通常ファイルだという通知です。`your fstab has been modified, but systemd still uses the old version` は、直後にスクリプトが実行する `systemctl daemon-reload` の前なので出ます。

イメージサイズは `--size` で変更します。値は整数の GB です（例: `--size 100G`）。60G は `/var/lib/docker` に入る volume とコンテナログが分け合う合計の上限です。ファイルシステムの metadata も容量を使うため、実際のデータ領域はこれより小さくなります。Docker 29 以降を新規にインストールして containerd image store（既定）を使う場合、イメージとコンテナ層は `/var/lib/containerd` に置かれ、XFS イメージの外（通常はルートディスク）に溜まります。その空きは別に確認します。XFS イメージは sparse ファイルですが、ホストにはその分の空きが必要です。

ある段階が失敗すると、スクリプトはそれより前の段階を逆順に元に戻します。fstab をバックアップから復元し、unmount し、作成した mount ポイントとイメージを削除し、原本を `/var/lib/docker` に戻してから Docker を再び起動します。Docker が新しいイメージで既に起動していた場合、その間に書き込んだ内容がイメージにあるため、イメージは削除せずにそのパスを表示します。

| 終了コード | 意味 |
| --- | --- |
| 0 | 準備が完了した。または既に準備済みで何も変更していない |
| 1 | 事前検査が拒否した。何も変更していない |
| 2 | 引数が正しくない |
| 3 | ある段階が失敗し、すべて元に戻した。Docker は元の data-root で再び動いている |
| 4 | ある段階が失敗し、元に戻す処理も一部失敗した。残った状態を出力に記す |

<a id="확인" />
## 確認

スクリプトは最後に data-root、mount オプション、quota probe を確認します。手順 1 のコマンドを再実行すれば、`xfs`・`prjquota` と probe の成功を自分で確認できます。`df -h`、`df -i`、`xfs_quota -x -c 'report -p'` で空き容量を確認します。

<a id="xfs-project-quota를-직접-켜기" />
## XFS project quota を自分で有効にする

Docker data-root 専用の XFS ディスクかパーティションがすでにあれば、スクリプトの代わりに mount オプションだけを有効にします。条件は次のとおりです。

- `docker info -f '{{.DockerRootDir}}'` が示すパスのファイルシステムが XFS であること。ext4 などほかのファイルシステムは Werft の quota 検査に合格しません。
- そのファイルシステムが `prjquota`（同じ意味の `pquota`）オプションで mount されていること。

`/etc/fstab` の項目は次の形です。UUID は `sudo blkid` で確認し、data-root が `/var/lib/docker` でなければそのパスを使います。

```text
UUID=<filesystem-uuid> /var/lib/docker xfs defaults,prjquota 0 0
```

quota のオプションは最初の mount でだけ効きます。`mount -o remount` では有効にならないので、Docker を止め、unmount してから mount し直します。実行中のコンテナはすべて止まるため、メンテナンス時間に行います。`docker.socket` unit がないホストでは、最初のコマンドからその名前を外します。

```bash
sudo systemctl stop docker.socket docker.service
sudo umount /var/lib/docker
sudo systemctl daemon-reload
sudo mount /var/lib/docker
sudo systemctl start docker.service
```

data-root がルートファイルシステム（`/`）にある場合は unmount できず、fstab のオプションだけでは有効になりません。カーネルの起動引数に `rootflags=prjquota` を加え（`rootflags` がすでにあればその値に足します）、再起動します。起動引数の変え方はディストリビューションごとに異なります。

<a id="켜졌는지-확인하기" />
## 有効になったか確認する

```bash
DATA="$(docker info -f '{{.DockerRootDir}}')"
findmnt -no TARGET,FSTYPE,OPTIONS -T "$DATA"
sudo xfs_quota -x -c 'state -p' "$(findmnt -no TARGET -T "$DATA")"
P="quota-probe-$(date +%s)"; docker volume create --driver local --opt size=64m "$P" && docker volume rm "$P"
```

`findmnt` のファイルシステムが `xfs` で、オプションに `prjquota` が必要です。`xfs_quota` の Project quota の項目は Accounting と Enforcement の両方が `ON` でなければなりません。最後の行は volume 名を 2 回出力すれば成功です。`quota size requested but no quota support` が出る場合は、まだ有効になっていません。

<a id="werft가-quota를-알아내는-방법" />
## Werft が quota を判定する方法

この節は Docker の設置が対象です。Kubernetes では scheduler は quota を検査しません。その上限は[ストレージと上限](/run-server/self-hosting/reference/storage)で確認します。

`EXECUTION_WORKSPACE_QUOTA=on` の場合、scheduler は mount テーブルや fstab を読んで判断せず、Docker Engine API で `local` ドライバーの `size` オプションを付けた probe volume（名前は `ap-quota-probe-` で始まります）を作ってみます。daemon が `no quota support` で拒否すれば失敗です。作成できると、worker イメージから helper コンテナ（`SYS_ADMIN`・`MKNOD` capability）を起動します。helper は `/proc/self/mountinfo` でその volume が XFS かを見て、`xfs_io` で volume 専用の project を確認し、`xfs_quota` で inode 上限を設定してから `xfs_quota` と `stat -f` で読み戻します。probe volume は検査の後に削除します。`scripts/test-ops.sh` の `preflight` と `deploy` も、同じ `size` オプションの probe volume を作ってみます。

検査に失敗すると、scheduler は worker を起動せず失敗で終了します。**自動で測定方式に切り替わることはありません。**測定で抑えるのは、運用者が `EXECUTION_WORKSPACE_QUOTA=off` を明示した場合だけです。このとき scheduler は probe を省略し、worker は作業領域を 1 分に 1 回までの頻度で測り、上限を超えた turn を止めます。二つの測定の間は一時的に上限を超えることがあります。単一サーバー設置の `scripts/test-ops.sh` は `off` を LocalStack の試験設置でだけ受け付けます。リポジトリ checkout のローカル Compose スタックは、値を指定しなければ `off` です。

ワークスペース設定の一般画面に出る quota の通知と `/readyz` の `detail.no_disk_quota` は、ディスクを検査した結果ではなく、api が受け取った `EXECUTION_WORKSPACE_QUOTA` の値が `off` かどうかを示します。ディスクを準備したら値を `on` に変え、api と scheduler に適用し直します。単一サーバー設置では env ファイルを直してから `scripts/test-ops.sh start` を実行します。`off` のときに作った workspace は `on` のままでは起動しないため、[workspace の移行](/run-server/self-hosting/migrate-workspaces)に従います。

<a id="자주-막히는-곳" />
## よくある問題

- `already exists` で拒否された場合は、以前の実行や手作業が残したパスです。中身を調べます。イメージや `/var/lib/docker.old` をサイズ変更や mkfs で再利用しないでください。
- 元に戻した後の再実行で `/var/lib/docker.xfs.img` や `/etc/fstab.before-prepare-xfs` が既にあるとして拒否された場合は、直前の巻き戻しが残したファイルです。Docker が新しいイメージで既に動いていた場合は、スクリプトもイメージを削除しません。イメージに残すべきデータがないことを確認し、unmount、fstab の復元、`daemon-reload` が終わって `/var/lib/docker` が原本に戻った後にだけ、`sudo rm -f /var/lib/docker.xfs.img /etc/fstab.before-prepare-xfs` で削除します。`/var/lib/docker.old` が残っていれば原本なので、削除せず先に戻します。
- `the trial XFS loop mount` で拒否された場合、このホストでは loop デバイスや XFS project quota を使えません。別のサーバーを使うか、Docker data-root 用の XFS ディスクを別に用意する移行計画を立てます。
- 終了コード 4 で data-root が元の位置に戻っていない場合、スクリプトは Docker を止めたままにします。この状態で Docker を起動すると空の data-root を使うため、出力に記された残りの状態を[元に戻す](#되돌리기)の順で片付けてから起動します。

<a id="되돌리기" />
## 元に戻す

新しい XFS で Docker を再起動した後に作成したコンテナ・volume・データは `/var/lib/docker.old` にありません。原本ディレクトリに戻すとその変更を失うため、先に新しいデータを別途保存し、復元する対象を決めます。sparse イメージは削除したデータの分だけ自動では縮まないため、ホストのファイルシステムの空き容量も監視します。

Docker と socket を停止します。新しい XFS が mount されていれば、使用中のコンテナがないことを確認してから unmount し、追加された fstab の項目をスクリプトが残した `/etc/fstab.before-prepare-xfs` と照合して戻し、`sudo systemctl daemon-reload` で systemd に復元した fstab を読み直させます。`/var/lib/docker.old` が原本です。元のパスが空であることを確認してから原本を戻し、Docker を起動します。新しいイメージや原本を削除せず、既存のコンテナ・volume の一覧が合っているか確認します。

元のデータディレクトリがあった環境では、unmount と fstab の復元が終わった後、空の mount ポイントだけを `sudo rmdir /var/lib/docker` で削除し、`sudo mv /var/lib/docker.old /var/lib/docker` で戻します。rmdir が失敗したら中のデータを削除せずに調べます。原本がなかった新規環境では、この移動を実行しません。
