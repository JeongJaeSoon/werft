---

워크스페이스에 사람을 들이는 길은 초대 링크다. owner나 admin이 받는 사람의 이메일과 역할로 링크를 만들어 직접 전하고, 받은 사람이 그 링크를 열어 수락하면 구성원이 된다. 플랫폼이 메일을 보내지는 않는다.

## 초대 링크 만들기

웹 콘솔의 **구성원** 화면에서 **구성원 초대**를 누르고 이메일과 역할을 정한 뒤 **초대 링크 만들기**를 누른다. 웹 로그인 cookie로 `POST /v1/invites`(`email`, `role`)를 불러도 같다.

- 초대는 owner와 admin이 한다. member가 부르면 403 `FORBIDDEN`이다.
- 역할 목록에는 지금 초대할 수 있는 역할만 나온다. admin은 owner로 초대할 수 없다(403 `OWNER_PROTECTED`).
- 링크는 만든 그 순간 한 번만 보인다. 서버는 토큰의 해시만 저장한다. 복사하지 않고 창을 닫으면 다시 볼 수 없으니, 그때는 초대를 회수하고 새로 만든다.
- 링크는 7일 동안 쓸 수 있다. 만료 시각은 링크 아래와 초대 목록에 보인다. 기한이 지난 초대도 목록에 **만료**로 남는다.
- 주소는 앞뒤 공백을 빼고 소문자로 비교한다. 같은 주소로 다시 초대하면 앞의 초대는 회수되고 새 링크만 쓸 수 있다.
- 이미 구성원인 주소는 409 `ALREADY_EXISTS`(`reason_code: already_member`)다. 계정이 정지된 구성원도 같다.
- 비활성화한 구성원은 목록에서 다시 활성화한다. 그 주소로 초대하려 하면 콘솔도 그렇게 안내한다. 비밀번호가 있는 계정은 다시 초대해 비밀번호로 수락해도 구성원 자격이 다시 켜지지만, 공급자 버튼으로는 수락할 수 없다(409). 공급자로만 로그인하던 계정은 초대로 돌아올 수 없다. 비밀번호가 없어 비밀번호 수락은 401이고, 공급자로 수락해도 409다.

초대를 만들 때마다 `invite_member` receipt가 남는다.

### API 응답

`POST /v1/invites`는 201과 아래 칸을 돌려준다. 링크는 이 응답에 한 번만 나온다. 응답에는 `Cache-Control: no-store`가 붙고, 초대 목록(`GET /v1/invites`)과 서버 로그에는 토큰도 링크도 나오지 않는다.

| 칸 | 내용 |
| --- | --- |
| `invite_id` | 초대 id. 회수할 때 쓴다 |
| `invite_token` | 수락 토큰 |
| `accept_path` | 수락 화면의 경로. `/invite/<invite_token>` 꼴이다 |
| `accept_url` | 받는 사람에게 건넬 링크. `CONSOLE_ORIGIN` 뒤에 `accept_path`를 붙인 `https://console.example.com/invite/<invite_token>` 꼴이다. `CONSOLE_ORIGIN`이 없으면 `null`이다 |
| `expires_at` | 만료 시각 |

`CONSOLE_ORIGIN`을 정하면 `accept_url`에 완성된 링크가 나온다. 정하지 않았으면 콘솔의 origin(`scheme://host[:port]`, 예: `https://console.example.com`) 바로 뒤에 `accept_path`를 붙여 건넨다. 콘솔 화면의 주소(`…/members` 등)에 붙이면 수락 화면이 열리지 않는다.

## 초대 회수하기

대기 중인 초대 옆의 **회수**를 누른다. API로는 `DELETE /v1/invites/{id}`이고 204를 돌려준다.

| 상황 | 응답 |
| --- | --- |
| 대기 중인 초대 | 204. 그 링크로는 더 수락할 수 없다(410) |
| 이미 회수한 초대 | 204. 아무것도 바뀌지 않는다 |
| 이미 수락한 초대 | 409 `INVITE_USED` |
| 없는 id | 404 |

회수하면 `revoke_invite` receipt가 남는다.

## 비밀번호로 수락하기

받은 사람이 링크를 열면 **초대 수락** 화면이 나온다. 먼저 초대받은 이메일로 쓰는 계정이 있는지 고른다.

- **아니요, 처음입니다**: 새 비밀번호(12자 이상)와 이름을 넣는다. 그 이메일로 계정이 생기고 초대의 역할로 들어간다. 이름을 비우면 이메일에서 정한다.
- **네, 계정이 있습니다**: 지금 쓰는 비밀번호를 넣는다. 비밀번호는 바뀌지 않는다. 비밀번호가 틀리면 401이고 초대는 쓰이지 않는다.

이 선택은 화면의 입력 칸만 바꾼다. 서버는 고른 답이 아니라 초대받은 이메일에 계정이 있는지로 정한다. 그 이메일의 계정이 이미 있으면 **아니요, 처음입니다**를 골랐더라도 넣은 비밀번호를 그 계정의 지금 비밀번호로 확인하고(틀리면 401), 이름은 쓰지 않는다.

수락하면 바로 로그인된다. 초대 토큰은 한 번만 쓴다.

## 로그인 공급자로 수락하기

켜진 [로그인 공급자](/run-server/self-hosting/sso)가 있으면 수락 화면에 **비밀번호 없이 가입** 아래 공급자마다 버튼(예: **Keycloak 계정으로 가입**)이 함께 나온다. 설치가 비밀번호 로그인을 꺼 두었으면 공급자 버튼만 나온다.

버튼을 누르면 공급자의 로그인 화면으로 갔다가 돌아온다. 공급자가 아직 아무 사용자에게도 연결되지 않은 계정을 보증하면 계정이 생기고 초대가 쓰인다. 계정의 이메일은 공급자가 보낸 주소가 아니라 초대받은 주소이고, 역할은 초대의 역할이다. 공급자로 만든 계정에는 비밀번호가 없다.

공급자 쪽에서 거절되면 콜백 화면이 이유를 알려 준다. 어느 경우든 초대는 쓰이지 않으니 받은 링크를 다시 열어 시도할 수 있다.

| 화면에 나오는 것 | 까닭 |
| --- | --- |
| 이 계정으로는 가입할 수 없습니다 | 공급자의 허용 도메인 밖의 계정이다 |
| 이 로그인 공급자로는 지금 가입할 수 없습니다 | 그 공급자가 지워졌거나 꺼졌다 |
| 가입을 시작한 주소와 돌아온 주소가 다릅니다 | 링크를 연 주소와 공급자가 돌려보낸 주소가 다르거나, 공급자 화면에서 10분 넘게 머물러 가입 흐름이 끝났다. 콘솔의 정식 주소에서 링크를 다시 연다 |
| 이 공급자 계정은 이미 다른 사용자에게 연결돼 있습니다 | 409 `ALREADY_EXISTS`. 그 공급자 계정으로 이미 다른 사용자가 로그인한다 |
| 이 공급자 계정을 같은 이메일의 콘솔 계정에 자동으로 연결할 수 없습니다 | 409 `LOGIN_LINK_REQUIRED`. 초대받은 이메일의 계정이 이미 있는데, 공급자가 그 주소를 증명하지 않았거나(다른 주소이거나 주소가 없음), 그 계정이 정지됐거나 비활성 구성원이거나, 그 계정에 같은 공급자의 다른 계정이 이미 연결돼 있다 |
| 가입하지 못했습니다 | 401. 공급자가 `email_verified: false`라고 한 계정이거나(설정과 상관없이), 검증된 이메일을 요구하는 공급자에서 주소나 `email_verified: true`를 받지 못했거나, 공급자의 응답을 검증하지 못했거나, 그 사이 초대가 회수·만료됐다. 서버는 어느 것인지 말하지 않는다 |
| 가입을 마치지 못했습니다 | 공급자 화면에서 그만뒀다 |

허용 도메인과 검증된 이메일 규칙, 초대 주소의 계정이 이미 있을 때의 동작은 [SSO 로그인 구성](/run-server/self-hosting/sso)에 있다.

## 쓸 수 없는 링크

| 화면 | 응답 | 까닭 |
| --- | --- | --- |
| 쓸 수 없는 초대입니다 | 410 `INVITE_EXPIRED` | 회수됐거나, 같은 주소로 새 초대가 나가 바뀌었거나, 7일이 지났다. 모르는 토큰도 이렇게 답한다 |
| 이미 수락한 초대입니다 | 409 `INVITE_USED` | 이 링크로 이미 수락했다. 로그인 화면에서 로그인한다 |
| 이미 이 워크스페이스의 구성원입니다 | — | 지금 로그인한 계정이 이미 구성원이다. 다른 계정으로 수락하려면 로그아웃하고 링크를 다시 연다 |

필요하면 초대한 사람에게 새 링크를 요청한다. 수락하면 `accept_invite` receipt가 남는다.
