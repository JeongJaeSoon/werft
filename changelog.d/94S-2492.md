### 운영자가 할 일

- **에이전트 GitHub 탭에 꺼진 채로 시작하는 권한 셋(자기 PR 머지, 리뷰 승인, workflow 직접 실행)을 두고, 콘솔에서 만드는 작성용 App이 workflow 파일 수정과 CI 결과 보기에 쓰는 권한을 늘 청한다**(JeongJaeSoon/werft#2393). migration은 없다.
  - 자기 PR 머지는 이제 워크스페이스 상한과 에이전트의 GitHub 탭 둘 다에서 켜야 한다. 워크스페이스에서 **자기 PR 머지**를 켜 둔 설치는, 올린 뒤 머지할 에이전트마다 GitHub 탭에서 켜고 저장한다. 그 전까지 머지는 `merge_off`로 거절되고, 거절의 `off_in`이 꺼진 곳(`agent`, `ceiling`, `both`)을 알려 준다. 켜기 전에 시작한 세션과, GitHub 탭을 저장한 적 없는 에이전트의 세션은 머지하지 않는다(시작할 때의 설정을 기록하지 않은 옛 세션만 지금 설정을 읽는다).
  - 리뷰 승인이 꺼진 에이전트의 리뷰 거절은 이유 code가 `feature_off`에서 `review_off`로 바뀐다. REST API는 전처럼 403 `GITHUB_REFUSED`이고 `error.details.reason_code`가 새 값이다. MCP 도구는 전처럼 `feature_off`로 답하고 `details.reason_code`에 `review_off`를 싣는다. 이유 code로 가르는 client는 새 값을 받는다.
  - 새로 만드는 작성용 App은 Contents·Pull requests·Workflows 쓰기와 Metadata·Actions·Checks 읽기를 청하고, **workflow 직접 실행 권한도 받기**를 체크하면 Actions를 쓰기로 청한다. 이미 있는 App은 바뀌지 않는다. Actions·Checks 읽기가 없는 App이 맡은 저장소에서는 전처럼 CI 결과 읽기가 `app_permission_missing`으로 거절된다(Workflows 쓰기는 workflow 파일을 고친 push에 든다). GitHub의 App 설정 Permissions & events에서 Actions와 Checks를 Read-only로, Workflows를 Read and write로 올리고, App을 설치한 계정에서 권한 요청을 승인한다.
  - 되돌릴 때는 JeongJaeSoon/werft#2373 이 든 판까지만 돌아간다. 그 판은 설정의 `merge` 키를 읽되 판정에 쓰지 않아, 머지가 다시 워크스페이스 상한만으로 정해진다. 에이전트에서 꺼 둔 머지가 되므로 돌아가기 전에 워크스페이스의 **자기 PR 머지**를 끈다. 그 판의 세션 GitHub 거절 목록에는 이 판이 남긴 `review_off` 거절이 나오지 않는다(receipt는 읽힌다). JeongJaeSoon/werft#2373 판으로 롤백하면 `review_off` 기록이 최근 20건(보는 사람에게 보이는 기록 기준)에 있는 동안 그 에이전트 GitHub 탭이 그려지지 않는다. GitHub 작업과 데이터는 그대로이고, 기록이 20건 밖으로 밀리면 풀린다. rolling upgrade 중 옛 web replica에도 같은 일이 잠깐 날 수 있고, 그동안은 옛 콘솔의 세션 화면도 그 세션의 GitHub 거절 목록(최근 10건)에 `review_off`가 있는 동안 그려지지 않는다. 그 판에서 에이전트 GitHub 탭을 저장하면 `merge` 값이 지워지므로, 다시 올린 뒤 머지할 에이전트는 다시 켠다. 그보다 앞선 판은 `merge` 키가 든 에이전트 설정과 그 설정으로 시작한 세션을 읽지 못해, 그 GitHub 작업이 `github_settings_unsupported`로 막힌다.
