### 운영자가 할 일

- **세션에 붙인 저장소에서도, 그 세션이 연 PR은 저장소가 에이전트의 목록 안에 있고 자기 PR 머지가 워크스페이스 상한과 에이전트 둘 다 켜졌을 때 머지한다**(JeongJaeSoon/werft#2404). migration은 없다.
  - 전에는 붙인 저장소의 머지가 스위치와 상관없이 `repository_not_allowed`로 거절됐다. 두 스위치를 켠 에이전트는 올린 뒤 Slack DM처럼 저장소를 붙여 일하는 세션에서도 자기 PR을 머지한다. push 요청·PR·카탈로그 검사를 지나 권한을 따질 때 스위치가 꺼져 있으면, 저장소가 목록 밖이어도 `merge_off`로 거절한다.
  - 머지하는 PR은 그 세션의 push 요청으로 플랫폼이 GitHub에 연 PR이어야 한다. 다른 세션의 push 요청은 전처럼 `not_found`다. 브랜치에 이미 있던 PR을 이어받아 기록한 것처럼 플랫폼이 열지 않은 PR은 새 이유 code `not_own_pull_request`로 거절한다(MCP 도구는 `github_refused`의 `reason_code`, HTTP 오류로는 `GITHUB_REFUSED` 403). 에이전트의 GitHub가 꺼져 있으면 스위치와 상관없이 머지하지 않는다. 이유 code로 가르는 client는 새 값을 받는다.
  - 되돌리면 붙인 저장소의 머지가 다시 `repository_not_allowed`로 거절된다. 바로 앞 판의 콘솔은 `not_own_pull_request` 기록을 code 그대로 보인다.
