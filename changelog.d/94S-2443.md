### 운영자가 할 일

- **모델 연결을 내부 네트워크 주소로 등록할 수 있고, 그런 연결은 proxy가 사설 주소 규칙과 설치 자신의 주소 목록으로 판정한다**(JeongJaeSoon/werft#2402). owner가 API 요청에 `acknowledge_private: true`를 넣어야 저장된다. 웹 화면은 아직 이 칸을 보내지 않는다. migration은 `provider_connections.network` 칸 하나다(expand).
  - **proxy를 먼저 올린다.** 새 API는 내부 네트워크로 등록한 연결의 grant에 `allow: private`와 `deny`를 싣고, 그 표시를 읽는다고 알린 proxy에만 낸다. 옛 proxy와 새 API가 섞이면 `EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST`에 없는 그런 연결의 세션 호출이 403(`egress_proxy_outdated`)이다. proxy를 올리면 돌아온다.
  - **Compose 배포는 내부 네트워크 등록을 쓰기 전에 DB와 metrics를 proxy가 닿지 못하게 한다.** Compose에서는 proxy와 postgres가 같은 network에 있다. API가 자기 interface 주소와 `DATABASE_URL`·`WORKER_GATEWAY_URL`·`AWS_ENDPOINT_URL`의 host를 스스로 막지만, 거기 나타나지 않는 주소(앞단 VIP, NAT 주소, Docker bridge gateway, host에 띄운 다른 서비스)는 API의 `EGRESS_PRIVATE_DENY_HOSTS`(쉼표 구분 이름 또는 IP, 포트 없음)에 적거나 방화벽으로 막는다. 포트가 붙은 항목이 있으면 API가 기동하지 않는다.
  - **Helm 배포는 egress-proxy의 NetworkPolicy에 Egress가 생긴다.** proxy는 DNS와, DB port(`networkPolicy.slack.databasePort`, 기본 5432)·metrics port(`api.metrics.port`, `metrics.port`, 기본 9464)를 뺀 TCP에만 나간다. forward 목록에 그 port의 목적지를 둔 설치는 `networkPolicy.egressProxy.restrict: false`로 끄거나 port를 옮긴다. 더 막을 port와 주소는 `networkPolicy.egressProxy.denyPorts`(53은 받지 않는다), `exceptCidrs`(DNS에도 적용된다. Pod를 ipBlock으로 맞추지 않는 CNI에서는 그 CNI의 정책을 쓴다)에 적고, 위의 host 목록은 `config.egress.privateDenyHosts`다.
  - **Helm 차트에 headless Service `<release>-api-pods`가 생긴다.** API가 모든 API Pod의 주소를 알아 내부 네트워크 연결이 다른 replica에 닿지 못하게 하는 데 쓴다. 차트는 자기 API Service 이름들을 `EGRESS_PRIVATE_DENY_HOSTS` 앞에 붙이고, Compose는 `api`를 붙인다. API는 이 이름들을 호출마다 새로 푼다.
  - **`EGRESS_CREDENTIAL_PRIVATE_ALLOWLIST`에 있는 기존 모델 연결은 API가 시작할 때 내부 네트워크 연결로 옮긴다.** 다시 확인받지 않고 receipt(`import_connection`, `by: env_import`)를 남긴다. 옮긴 연결은 새 proxy에서 loopback과 설치 자신의 주소에 닿지 못한다. 지금 그런 주소로 풀리는 연결은 옮기지 않고 전처럼 env 목록으로 동작하며, API 로그 `Connections on the private allowlist may not be registered as private`가 그 연결 id를 적는다. 그 연결은 다른 주소로 다시 만든다.
  - 내부 네트워크 연결의 호출은 API가 설치 자신의 주소를 다 모으지 못하면(배선의 이름이 풀리지 않거나 256개를 넘으면) 503으로 거절된다. 로그의 `private_deny_unavailable`로 보인다.
  - 앞선 이미지로 되돌려도 된다. 되돌린 동안 내부 네트워크로 새로 등록한 연결(env 목록 밖)의 호출은 proxy가 403으로 닫고, 데이터는 그대로다.
