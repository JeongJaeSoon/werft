### 운영자가 할 일

- **에이전트 GitHub 권한 스위치를 읽을 때 그 판이 모르는 키는 빼고 판정하고, 그 에이전트의 GitHub 작업을 막지 않는다**(JeongJaeSoon/werft#2373). 대상은 에이전트 GitHub 설정(`agent_github_settings.features`), release pin(`policy_pins.github.features`), 세션 시작 snapshot(`sessions.github_policy_start`)이다. 전에는 권한 스위치에 그 판이 모르는 키가 있으면 그 설정을 읽지 못해 에이전트와 세션의 GitHub 작업이 막혔고(gate는 `github_settings_unsupported`로 거절했다), 그런 pin을 가진 release는 조회도 실패했다. 저장된 값은 지우지도 바꾸지도 않는다. release는 ID가 저장된 pin을 해시하므로 release를 읽을 때는 그 키를 남기고, 권한 판정에서만 뺀다. 쓰는 길과 검증은 그대로 엄격하다. 알려진 스위치의 값이 잘못되었거나 스위치 밖(GitHub 설정의 다른 최상위 키, workflow 허용 목록 항목의 키)에 모르는 키가 있으면 전처럼 읽지 못한다. migration은 없고 따로 할 일도 없다.
  - 이 판이 다시 쓰는 값(세션 시작 snapshot, 첫 저장으로 만드는 설정, 앞선 release의 pin을 물려받아 만드는 release, 에이전트 GitHub 설정 조회 응답)에는 모르는 키를 넣지 않으므로 앞선 이미지로 되돌려도 된다. release 조회 응답은 저장된 pin을 그대로 돌려준다. 이 판 뒤에 권한 스위치를 더한 판을 쓴 설치는 그 판이 쓴 값이 남으므로 이 판보다 앞으로 돌아가지 않는다.
